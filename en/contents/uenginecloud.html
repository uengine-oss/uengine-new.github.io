Open Source PaaS · Kubernetes

uEngine Cloud

Kubernetes-based developer self-service PaaS portal

GitHub Watch the demo Product Brochure (PDF)

2026 product demo · about 6 minutes, from app creation to zero-downtime switchover and node migration

Developers focus on code,
deployment and operations happen in the portal

uEngine Cloud is a developer self-service PaaS portal running on Kubernetes. Create a service from the catalog, and Git repository creation, image builds, and dev, staging, and production deployment follow in a single flow.

Developers push source code, while operators check resources, logs, metrics, and deployment status on the same app screen. Verified images are promoted to production without rebuilding, and traffic switchover and rollback to the previous version are handled in the portal.

Key features

From service creation to operations, these are product screens running on a real Kubernetes cluster.
Click any screen to enlarge it. Apps and figures shown are from a demo environment.

Start a service from a template

Pick a template from the catalog, set a name and resources, and a Git repository and first deployment pipeline are ready. Reuse your organization's standard projects.

Push your source code and an image build job runs inside the cluster. The resulting image is registered in the registry and deployed to the stage you specify.

Promote the image verified in development to staging and production. No rebuild at each stage, so the version you deploy stays consistent.

How It Works

01

Choose a template

Pick an app type from the catalog and set the name and resources. A repository and first build are ready.
02

Change code and build

Push code and the image is built inside the cluster and deployed to the dev stage.
03

Verify and promote

Promote the image verified in dev to staging and production, then switch traffic.
04

Observe and improve

Check logs and metrics, then confirm the switch. If needed, roll back to the previous slot or a snapshot.

A deployment strategy for every service

Five deployment strategies you select and tune in the portal
StrategyHow it works
Blue-greenDeploys the new version to the opposite slot and switches traffic. The previous slot is kept until you confirm.
CanarySets the share of traffic sent to the new version and adjusts it gradually.
A/B testingRoutes requests carrying a specified request header to the new version.
Session affinityEnsures requests from the same user are routed to the same instance.
Rolling speedControls the share of instances added or removed at once during replacement.

On-premises · Open source

Install and extend to fit your in-house environment

Set up the portal, repository, registry, and auth server on your in-house Kubernetes environment. Pre-import the required images and it installs on air-gapped networks too.

Provides OAuth 2.0/OIDC-based authentication, admin and regular user roles, and group management. Integration with your existing repositories, registries, and identity systems is configured to fit your environment.

The source is published under the MIT license, so templates and screens can be extended to match your organization's standards. We also review installation setup, operations documentation, training, and a pilot service rollout with you.

Product background and key references

Starting from uEngine BPM, released in 2003, the product evolved into the open-source PaaS of the OCE (Open Cloud Engine) alliance in 2013 and MSA-based DevOps in 2018. Today it supports Kubernetes and connects the design and implementation tool Robo Architect with deployment and operations. Robo Architect integration

Connect the services you design to deployment

Robo Architect analyzes requirements, then designs, implements, and verifies microservices. The generated artifacts are deployed to uEngine Cloud and run in a Kubernetes environment.

Spec and code changes are managed in Robo Architect; build, deployment, and runtime status are managed in uEngine Cloud. Design to operations, connected in a single development flow.
