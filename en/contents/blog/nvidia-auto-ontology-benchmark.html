A semantic layer for AI agents, measured against NVIDIA Auto Ontology

Date: November 06, 2026

  1. A dictionary and a map

Open a company database to an AI agent as it is, and the answers go astray. It writes SQL from table and column names alone, mixes up revenue definitions that differ by department, and invents table relationships that don't exist. That is why a semantic layer sits between the data and the agent: what each column means and how the tables relate, organised in advance.

In November 2026 NVIDIA released this semantic layer as open source: Auto Ontology. It reads a company database's metadata and builds a glossary, verified formulas and the joins between tables, and agents write SQL from that.

Think of a dictionary. It tells you exactly what a word means, but it won't find the way to your destination or drive you there. Auto Ontology is an accurate dictionary. uEngine's Ontological Studio is closer to a map: it shows how data scattered across systems connects, follows those connections to the answer, and, once a person approves, carries out the work in the business systems.

We compare how the two products handle the same jobs, and present three things we learned from NVIDIA and put into Ontological Studio straight away.

  2. Giving both products the same job

We compared five jobs on a sample company's purchasing ERP, logistics WMS and customer CRM data. The Ontological Studio column is what actually ran. The NVIDIA column is the behaviour we confirmed in the published source code and official documentation; we did not install and run it.

  3. Three things we learned from NVIDIA and adopted

The comparison also showed where Auto Ontology is better equipped. We put three of those into Ontological Studio straight away. Tutorial chapters 22–24 walk through them with videos.

Finding relationships even without keys

Auto Ontology accepts a join only when the parent column has no duplicate values. We adopted that rule and added one: at least 80% of the child values must be in the parent. Status, quantity and date columns are left out from the start. The database measures the columns without copying the source (SHOW COLUMN STATS, SHOW VALUE OVERLAP), and Studio suggests relationships with that as the evidence.

Measuring 13 tables in the three sample databases took one second. Seven relationships were suggested and 56 candidates rejected. Auto Ontology skips inference without an embedding key; our judgement works without AI.

Every suggestion shows how many sampled values matched, whether the parent values are unique, and which naming rule applied.

Checking first whether it can answer

Auto Ontology's check_answerable returns, as a number from 0 to 1, the share of the question's entities found in the data. We took that idea and made it five verdicts: answerable, partly answerable, not yet answerable, needs clarification, and not published. The verdict comes from rules, not an AI guess. A question that matches a golden question verified by actually running it at build time is answered along that verified path, and a number in the question is checked against real instances. "S-KR-01", for example, was confirmed as the supplier 「Hanbit Precision」.

"What was last quarter's advertising spend?" — answerability is judged first, and the agent does not build an answer from data that isn't there.

Source passwords stay outside the database

Auto Ontology keeps connection details outside the database when Vault is on. We changed our default so that this holds without Vault: on the desktop the password is in the OS keychain, on a server in your Vault or OpenBao, and the database keeps only a reference such as keychain:ds/erp. When the source password changes, one Change password does it, and the virtual nodes on top stay as they are.

We started and stopped the real app three times and checked 21 things: that no password is left in the user mappings or the server log, and that losing a keychain item breaks only that datasource.

  4. Where NVIDIA is ahead

  • Source connectors: ten, including Snowflake, Databricks, ClickHouse and Trino. Ontological Studio has four: PostgreSQL, MySQL, Oracle and SQL Server.
  • Running for many users: SSO, role-based permissions and token revocation. Ontological Studio desktop is an app for one person.
  • Public evaluation: a separate repository measures SQL accuracy on public benchmarks. We verify every ontology with golden questions, but have no public numbers yet.
  • License: Apache-2.0 makes it easy for a company to adopt as is. Ontological Studio is AGPL-3.0 with a commercial license.

  5. Which to choose

  • If the goal is accurate SQL answers over one cloud data warehouse, Auto Ontology fits well.
  • If the data sits in several systems such as ERP, MES and WMS, and you need to query across them without moving it and carry the work through, Ontological Studio fits.
  • The two can work together: the terms and formulas one has organised are good material for the other's ontology.

An agent needs more than an accurate dictionary. It also needs a map that shows how the data connects, and hands that do only the work that was approved.
