Task Automation (RPA)

uEngine RPA

Describe a repetitive task in plain language, AI builds the automation, and from then on a robot handles it every day with no AI cost

GitHub Watch the demo

Build with AI, run at no cost

uEngine RPA is a tool that hands the computer tasks people repeat every day, such as tidying spreadsheets, entering data into internal systems, compiling reports, and sending emails, over to a robot.

You build the automation by telling AI what you need in plain language, and the finished automation is executed by a robot that follows a fixed sequence. So the AI cost is paid once at build time, running it is free no matter how many times you do it, and the result is the same every time.

The automation you build connects as a step in a uEngine BPM process, so human work and robot work run together in a single flow.

Just write it the way you would explain your work: "Open the order spreadsheet, pick only the rows over KRW 1,000,000, and register them in the internal system." AI selects the steps it needs, builds the automation flow, and draws it on the canvas.

Blocks that express your workflow

Go beyond a simple sequence and draw conditions, loops, and exceptions as blocks. Nest blocks inside blocks to carry real business rules over as they are.

Branching

IF · ELSE IF · ELSE

Send work down different paths depending on a condition, such as "if the amount exceeds KRW 1,000,000, request approval; otherwise register automatically." Multiple conditions can be combined with AND/OR.

Loops

FOR · WHILE

Four ways to loop: per Excel row, per file, from 1 to 100, or across two lists side by side. WHILE runs as long as a condition is true, such as "until the file arrives," and a maximum iteration limit prevents infinite loops.

Exception handling

TRY · EXCEPT · ELSE · FINALLY

When a site is slow or a file is missing, the robot recovers instead of stopping. Set a different response for each error type, and specify what to do at the end (such as closing windows) whether it succeeds or fails.

Flow control

BREAK · CONTINUE · RETURN

End the loop as soon as you find what you were looking for (BREAK), skip just that item (CONTINUE), or finish and return a result (RETURN).

Grouping

GROUP

Bundle several related steps under one name so they read as a single unit in the execution log.

Your own components

User keywords

Save recurring procedures like "log in to the company portal" under a name and call them anywhere as a single block.

Variables that hold values

Values that change often or are used in many places are stored under a name and pulled into any block with the $ button.

Type Notation Use it for
Scalar${name}A single value, such as a site URL, an owner's email, or a threshold amount
List@{name}A sequence of values, such as files to process or branch names
Dictionary&{name}A table pairing names with values, such as branch → owner
Environment variable%{name}Values that differ per machine, such as passwords and paths

How it works

Four steps are all it takes to hand off a task

1. Describe the task

Write it in everyday language, such as "Every Monday, gather the branch sales spreadsheets, build a summary table, and email it to the team lead."

2. AI drafts the automation

A draft automation appears on the canvas with the right components selected and wired in order. Review the blocks, drag in any missing steps, and refine the values.

3. Run it

Press Run and the robot gets to work immediately, with progress shown at the bottom of the screen. Wherever it gets stuck, fix the value in the block and run again.

4. Hand it off and forget it

Schedule the saved automation or attach it as a step in a uEngine BPM process. From then on, the robot repeats it with no AI cost.

AI cost once at build time, execution is free

This is the biggest difference from asking an AI to do the task every time. AI is used only when designing the automation; the actual work is handled by the robot.

At build time · once

Design with AI

Describe the task and AI draws the automation. This is the only time AI is used. Edits work the same way: once.

At run time · daily

Robot runs it repeatedly

The finished automation is executed by a robot in a fixed sequence. No AI calls means no cost and no worry about answers changing.

Predictable cost. A thousand runs a day adds nothing to your AI bill.
Same input, same result. Safe to use even for work that faces audits and regulatory requirements.
Runs without external connections. The robot keeps running on networks with no internet access. The AI used for design is limited to what your company allows.

One flow with uEngine BPM

It does not end with a robot running on its own. An automation built with uEngine RPA attaches as a step (script task) in a uEngine BPM process, so human work and robot work follow each other in order within a single business flow.

HumanReceive purchase requestThe requester submits a request form
→
Robot · uEngine RPACollect quotes · build comparison tableVisits vendor sites, gathers quotes, and compiles them in Excel
→
HumanTeam lead approvalReviews the comparison table and approves
→
Robot · uEngine RPARegister ERP purchase orderEnters the approved details into ERP and reports back the result

Robot steps inside the process

In the BPM process model, define the robot's step as a script task and assign a uEngine RPA automation. When its turn comes, BPM wakes the robot, receives the result, and passes it to the next step.

Data flows through as-is

Values a person entered in the previous step are passed to the robot as variables, and what the robot produces (files, tables, status) appears on the next person's screen. Nothing needs to be copied over by hand.

Manage and track in one place

Who did what and when, and how far the robot got, are all recorded together in BPM's work history. If the robot fails, the work is returned to the owner as a task and a person takes over.
