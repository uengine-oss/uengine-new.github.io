Hands-on consulting & training from uEngine, the team behind MSA School

uEngine Solutions runs MSA School, a dedicated learning center for cloud-native applications (CNA), and delivers the entire journey as consulting and training: from domain-driven design (DDD)·EventStorming to microservices implementation patterns and deployment/operations.

Led by CEO Jinyoung Jang, a SAFe certified consultant and technical advisory member of the Digital Platform Government, our team of hands-on experts draws on MSA prototyping consulting experience across many industries to go beyond theory and build real architecture transformation in your organization together with you.

① Consulting Services — We Transform Systems

The engagement proceeds in four stages — legacy assessment → service boundary design → pilot implementation → operational stabilization — with the Robo Analyzer (assessment) and Robo Architect (implementation) tools integrated at each stage.

② Training Services — We Grow People

Using the Cloud Native Maturity Model (CNMM) as the benchmark, we internalize team capability through public seminars (Parts 1–3) covering design·implementation·deployment and a roughly six-month regular Professional program (Levels 1–3·capstone).

Consulting Service

Consulting Process

From assessment to operational stabilization, people (experts) and tools (Robo Analyzer and Robo Architect) work side by side

1. Assessment

Robo Analyzer automatically analyzes the legacy system while consultants interview stakeholders on the current state.

2. Service Boundary Design

Using DDD·EventStorming, we classify core and supporting domains and design bounded context boundaries together with you.

3. Pilot Implementation

We carry out pilot development applying microservices patterns, and Robo Architect automatically implements validated code.

4. Operational Stabilization

We build GitOps-based deployment automation plus monitoring·incident response, and embed them in your organization.

Consulting Tool ① Assessment

Robo Analyzer — Consulting That Starts with Assessment

The first step of any engagement is always an ‘as-is assessment’. Robo Analyzer automatically analyzes the existing legacy system to identify tight-coupling points, service decomposition candidates and migration priorities, which are then applied directly to the service boundary design of the real system.

Rather than relying on gut feel to analyze legacy systems, we design DDD-based service boundaries together with you on the quantitative evidence our tools produce.

Automated legacy code analysis → candidate service decompositions
Diagnostic results feed directly into hands-on DDD·EventStorming design exercises
Migration priorities set on quantitative evidence
Explore Robo Analyzer

Consulting Tool ② Implementation

Robo Architect — From Design to Automated Implementation

The Aggregate·EventStorming models and microservice implementation patterns derived during consulting are automatically turned into working code through the Spec-Driven Development engine of Robo Architect. Training embeds design capability in your team while tooling secures implementation speed, and the two levers move together.

The domain model and service boundaries derived during consulting carry straight into Robo Architect proposals, so specification and implementation never drift apart.

Designed domain model → handed off as a Robo Architect proposal
Automatic generation of microservice-pattern code·tests
Spec↔implementation alignment anchors consulting outcomes in the field

Education Program

Talent Maturity Model (CNMM)

A cloud-native maturity model we developed in-house by integrating CNCF and the Scaled Agile Framework. Every course and assessment is designed on the model's level-by-level learning objectives (LOs), and each individual's achievement is plotted on the model to become a capability development roadmap.

Perspective Lv1 Early Lv2 Inception Lv3 Expanding Lv4 Mature
Functional Decomposition Separation by function·use case Interface definition per service Domain context separation (Anti-corruption Layer) Domain events·CQRS model
Data Single DB·ACID (2PC) Schema per Service DBMS per Service (polyglot persistence) Event-based management·event sourcing
SW Architecture Server-side rendering·session security MSA-oriented framework (Spring Boot) Client-side rendering·token security (OAuth2) Polyglot + Service Mesh
Infrastructure·Deployment Continuous build·manual installation Continuous deployment·one service per VM Containers·Kubernetes, Blue/Green deployment PaaS·multi-cloud
Team Structure Functional teams with separate Dev·QA·Ops Collaboration on a shared service model Product team per service Fully accountable team per domain (“You build it, you run it”)

Talent development targets — Architects: 80% reach Lv3·50% reach Lv4 / Developers: 100% reach Lv2·50% reach Lv3

Training ① Public Seminars

Design·Implementation·Deployment Seminar Series (Parts 1·2·3)

Using a public-service civil-complaint handling exercise and the Korea Workers' Compensation and Welfare Service ‘industrial accident claim’ case as running examples, we apply patterns to real requirements instead of stopping at theory. The complete lecture materials are available as PDFs right away.

Part 1. Design

DDD and EventStorming

Covers the strategic patterns of Domain-Driven Design (bounded contexts; core·supporting·generic domain classification) and the tactical patterns (Aggregates·invariants). Participants derive domain events·commands·actors·policies with five-color-sticky EventStorming, and in the public civil-complaint handling exercise they go hands-on with MSAez.io, from EventStorming all the way to code generation on the Korean eGovernment Standard Framework (eGovFrame).

Bounded Context Core·Supporting·Generic Domains Aggregates·Invariants EventStorming (5-color stickies) Hexagonal·Clean Architecture eGovFrame (Korean eGov Standard Framework) MSAez.io Hands-on (Civil-complaint App)
Download Slides (PDF)

Part 2. Implementation

Microservice Patterns

With the Korea Workers' Compensation and Welfare Service ‘industrial accident claim’ case as the running example, we isolate failures with an API Gateway·circuit breakers and manage distributed transactions with SAGA (orchestration·choreography). We build data projections with CQRS·event sourcing·EDA (Kafka) and cover the full implementation lifecycle, through contract testing·JWT/Keycloak security·container packaging.

API Gateway·Circuit Breaker SAGA (Orchestration·Choreography) CQRS·Event Sourcing EDA·Kafka GraphQL·BFF Contract Testing (CDC) JWT·Keycloak Security Container Packaging (Docker)
Download Slides (PDF)

Part 3. Deployment/Operations

Microservice Deployment/Operations

Covers everything from service dockerization and deployment model design (high availability·autoscaling·resilience) to GitOps (ArgoCD)-based deployment automation and Kubernetes orchestration using AIOps tools such as K8sGPT. Operational stability is completed with the Istio service mesh, PLG·Zipkin observability, and Cloud Native SRE based on SLI/SLO/Error Budgets.

Docker Packaging Deployment Model Design (HPA·Resilience) GitOps·ArgoCD Kubernetes Orchestration AIOps (K8sGPT) Service Mesh (Istio) Observability (PLG·Zipkin) Cloud Native SRE (SLI/SLO)
Download Slides (PDF)

Training ② Regular Program

Cloud Native Professional Program (approx. 6 months)

An intensive development program targeting progression from maturity model Lv2→Lv4. From AI-based orientation to the capstone project, every stage is validated with a mini project.

Stage Duration Goal Key Content
Orientation Week 1 Understanding the AI-driven development process Hands-on with Cursor IDE·GPT-Engineer, trying AIOps tools such as Kubectl AI·K8sGPT, forming teams·missions
Lv1 Fundamental 1 month VM-based app development skills (CNMM Lv2) Java·object orientation·design patterns·UML, Spring Boot·JPA·REST, React.js·MUI front end, mini project
Lv2 Intermediate 1.8 months Cloud-native app implementation (CNMM Lv3) DDD·EventStorming, microservice implementation, Kafka·Saga (Axon), API gateway·authentication/authorization, GraphQL·CQRS, contract testing, mini project
Lv3 Advanced 1.3 months Competitive cloud app design (CNMM Lv4) Agile planning·analysis (SAFe·BDD), Docker packaging, AWS·Azure Kubernetes, service mesh, GitOps·CI/CD, LLM app development
Capstone Project 3 weeks Mastering real-world project delivery Two iterations of project planning (Biz) → implementation (Dev) → operations (Ops) → improvement, with a final presentation evaluated by a review panel

Training ③ Program Operations

From Selection to Follow-up

We go beyond attendance tracking to systematically manage the entire cycle of selection·operations·projects·evaluation

1. Selection

Trainees matched to the program goals are selected through Java·Spring·PaaS pre-assessments and a skills diagnostic survey.

2. Operations

HRD-Net-based attendance management, daily satisfaction surveys, real-time cloud IDE screen support, and an AI-powered self-service troubleshooting environment.

3. Projects

RFP-based mini projects at each stage and a final capstone project, combined with comprehensive written·practical assessments.

4. Follow-up

Skill sets are analyzed with individual·team Radar Charts to recommend supplementary learning, and the top 10% are deployed to live projects immediately.
