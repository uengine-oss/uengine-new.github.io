Robo Analyzer

The connection between code and data, as a graph you can read.
Analyzes legacy source code together with database schemas to show function calls and table read·write relationships in a single graph. From any point, you can drill down to the original source code.

What you can't learn from reading code alone

In an aging system, reading the code alone rarely reveals the real call flow. Documentation and code disagree about where tables are read and written.

Robo Analyzer focuses on understanding the current system from code and data evidence. Automating the specification, design, and implementation that follow analysis is the job of a separate product.

What sets Robo Analyzer apart

Structure computed without an LLM

Structure, relationships, clusters, and risk levels are computed without an LLM. AI is used only to attach meaning.

Analyzes broken code too

Attempts recovery only on the failed parts; if that fails, it leaves them and moves on. The originals are never modified.

Progress in real time

In both parsing and analysis, the stage, console, and node counts keep updating long before completion.

Search in business language

"The part that reserves inventory and cancels if there's a shortage" — finds the relevant code from the sentence as written.

Proven by the source

Every result links to an actual file and line number. No diagrams without evidence.

Production DB is read-only

Only queries are allowed, writes are blocked, and connection passwords are never stored anywhere.

It doesn't stop at showing structure

Ever been handed code that doesn't even compile?

It's normal for legacy source to include files with broken syntax. Valid files are processed as-is; only the failed parts get a grammar-rule-based recovery attempt. If that still fails, only that part is left behind and processing moves on to the next file.

By default, original source files are never modified.

Down to business rules and risk points

Extracts the decision conditions scattered through the code as rules — for example, “allow withdrawal if the balance is greater than 0.” They are organized into rules, examples, and questions needing confirmation, and linked to the related tables.

For each function, it computes how often it is called, how many calls it makes, code length, circular references, and table coupling, then assigns a Low·Medium·High grade.

Frequently Asked Questions

Which source languages can be analyzed?

Java, C, Python, Oracle PL/SQL, and PostgreSQL are detected automatically from file contents. Users never need to specify the target language.

Can I start without connecting a production DB?

Yes. Analysis can begin with source code and DDL alone. If you also register a production DB, table accesses found in the code can be checked against the actual schema.

Is it safe to connect to a production DB?

Only query statements are allowed; writes, changes, and deletes are blocked. The server caps the number of rows fetched, and connection passwords never appear in storage, responses, or logs.

What happens if some files have broken syntax?

It retries only the failed portion; if that still fails, it leaves just that part behind and moves on to the next file. The analysis as a whole never stops, and the original source files are never modified.

Are the analysis results made up by the AI?

Structure, relationships, clusters, and risk scores are computed without an LLM. AI is used only to attach meaning, such as summarizing functions or phrasing rules in plain language.
