Our Products

Ontological Studio

A desktop studio where you build ontologies, ask them questions, act on them and use them as apps.
One installer holds the data fabric, the graph database and the agents.

Download Watch the demo Tutorial

macOS (Apple Silicon · Intel) · Windows 10/11 (x64) · Open source · Install guide · Step-by-step tutorial with videos

Answers are never in one place, and work doesn’t end with the answer

“Which finished products contain the part with the soldering defect, and who is the contact at that supplier?” — the answer to a question like this is scattered across quality reports, the purchasing ERP and the logistics system. Once you have the answer, you still have to hold purchase orders, expedite shipments and keep an eye on the situation every day.

Ontological Studio connects this whole flow in one app. Connect documents and databases without moving the data, and an agent designs the ontology around the questions it must answer (Golden Questions) and the instructions it must carry out (Golden Commands). Questions are answered with evidence by following relationships. Instructions become actions that call the APIs of your registered business systems, run after a person approves them, and can be undone when needed. On the same ontology, you build business apps just by describing them — dashboards wired to widgets, or apps whose code an agent writes.

Demo 1 Build from a document — design the ontology, check it against Golden Questions, publish it and get answers with evidence (3:35)

Demo 2 Run actions — find the targets with a question, then approve, execute and cancel an action built from a Golden Command (3:39)

Demo 3 Code apps — describe an app and a coding agent writes it on top of the ontology (3:32)

Key Features

Connect → build → publish → ask → act → apps, all on the same ontology

From one document to an ontology

Pick the documents or databases to work from and write down what the ontology must answer (build intent and Golden Questions). The agent designs the concepts and relationships, loads the facts as instances, then asks the Golden Questions itself to check that the answers come out. A person decides whether to publish.

The agent drafts the build intent and Golden Questions for you.
Design classes and relationships → load instances → self-check
Only published ontologies are used for questions and apps.

Answers with evidence

You don’t have to tell it what to look for or in what order. The agent reads the published map and follows the relationships — from a quality issue to the part, the finished product, the supplier and the contact — to answer. The evidence stays on screen.

Graph RAG that follows the graph’s relationships
Evidence nodes and relationships shown with every answer
Available to other AI agents over MCP.

A data fabric without copies

Connect PostgreSQL, MySQL/MariaDB, Oracle and SQL Server with just their connection details and expose tables as virtual nodes. Nothing is copied: the source is read at query time, so one Cypher query can span databases on different engines.

Connections, table previews, virtual nodes and virtual relationships on one screen
Cross-database Cypher measured at about 140 ms, with non-ASCII text intact
Sources are read-only — writes happen only through actions

Golden Command → action

Write down what this ontology should be able to do as Golden Commands, and the agent explores the APIs of your registered business systems. From them it builds the action, the compensation that undoes it, and the policy that decides who can run it on which targets, then checks everything with a dry run. Every run goes through human approval.

Plan → approve → execute (saga) → compensate on cancel
Three sample systems built in (purchasing ERP, logistics WMS, customer CRM)
Check the results in the source tables on the Data Sources screen

Dashboards from @mentions

In the prompt box, pull in classes and properties with @ or drag them from the resource tree, and describe the screen you want. For mentioned classes, the engine looks at the data and picks the widgets right away (about a second); the agent turns the rest of the request into a proposal (a diff). A person clicks to apply it.

Classes, properties and widgets appear as chips in your sentence.
Golden Questions are offered as examples.
Charts follow the light and dark themes too.

Code apps the agent writes

Choose “Code app” in the same prompt box, and a coding agent (Claude Code or Codex) runs queries against the ontology to check them, then writes the app code. The left side shows the queries it checked and the files it wrote; the preview on the right refreshes whenever a file changes. Tell it what to fix and the agent changes it in the same session.

Vue app code (HTML, JavaScript, CSS) — runs as is, no build step
Data is reached only through a read-only query SDK.
Open it in an app tab and use it like any business screen

Ontological Portal

A console for working with the graph directly. Type natural language instead of Cypher in the query box, and the agent turns it into Cypher using the schema, checks it once and runs it. When you type Cypher yourself, you get completion for labels, relationship types and properties, and syntax highlighting.

Natural language → Cypher (if it fails, one retry using the engine’s message)
Completion for labels, relationship types and properties
Schema map and point-in-time queries

One installer, all on your computer

One installer holds PostgreSQL with the Ontological extension (the data fabric), the Bolt gateway, Studio, the action executor and the sample systems. The agents use the Claude Code or Codex CLI you are already signed in to on this computer, so you don’t need a separate API key.

No Docker, no Neo4j
Studio and the Portal open side by side in tabs.
Your data lives in your user folder; delete it to start over.

How It Works

People say what they want and make the decisions. Agents handle design, queries and code; the executor runs actions once they are approved.

1. Connect

Upload documents, or register source databases and business systems. The data stays where it is.

2. Build

The agent designs and checks the ontology against your build intent, Golden Questions and Golden Commands.

3. Publish

A person reviews and publishes it. Only published ontologies are used for questions, actions and apps.

4. Ask

Ask in plain words and get answers with evidence, following the relationships. In the Portal, query directly with Cypher.

5. Act

Instructions become execution plans and, once approved, run through the business systems’ APIs. Cancel, and compensation steps undo the run.

6. Apps

On the same ontology, put together dashboards or hand the app code to an agent.

Golden Questions and Golden Commands

A build is measured by two things: what the ontology must answer, and what it must do. More in the tutorial

Golden Question — a question it must answer

A question this ontology must be able to answer, such as “Which finished products contain the part with the soldering defect?” The agent works backwards from the question to the concepts, relationships and sources it needs, designs the schema first, and once the build is done, runs the question itself to check that the expected answer and evidence come out.

Where schema design starts — the relationship path for each question comes first
The acceptance test for a build — if an answer falls short, the schema and mappings are refined
Offered as example questions in the apps too

Golden Command — an instruction it must carry out

An instruction to carry out on this ontology, such as “Switch the delayed shipments to urgent delivery.” The agent explores the APIs of your registered business systems and builds the action that carries it out, the compensation that undoes it, and the policy that decides who may use it on which targets, then checks them with a dry run.

Where action design starts — each execute API is paired with a compensating API
Runs go plan → approve → execute; cancel, and compensation runs in reverse order
A cancel instruction is handled by the compensation flow, with no separate action

How an ontology gets built

Guided by the intent and the Golden Questions, the agent repeats design → extract and link → run the questions → check. Once the criteria are met, a person reviews and publishes.

What’s in the installer

No separate Docker or Neo4j. When you start the app, the components below run together on your computer, and they stop when you quit.

Component What it does
PostgreSQL 16 + the Ontological extension The graph store and the data fabric. Source database connectors (postgres_fdw, mysql_fdw, oracle_fdw, tds_fdw) read the virtual nodes. More about Ontological DB
Bolt gateway The Neo4j-compatible Bolt protocol — the only way Studio, the Portal and apps reach the graph with Cypher.
Studio backend (with MCP) The Build, Ask & Act, actions and apps screens, plus the MCP tools AI agents use.
Coding and build agents Connects the Claude Code or Codex CLI on this computer through cliagents (no API key needed). Without one, it uses an OpenAI key.
Kinetic Action executor Plan, policy check, approval, saga execution and compensation. It calls the business systems with tokens the app signs.
Ontological Portal Cypher console, schema map, natural language → Cypher, completion.
Sample ontology and business systems The “Supply Chain Operations” ontology with a purchasing ERP, a logistics WMS and a customer CRM — follow the videos step by step.

Download

Install it and try it now

The first launch prepares the database, the sample ontology “Supply Chain Operations” and the sample business systems (purchasing ERP, logistics WMS, customer CRM). You can follow the videos step by step.

macOS

macOS 13 or later · Download the DMG for your Mac’s chip, open it and drag the app to Applications. (To check your chip: Apple menu → About This Mac)

Apple Silicon (M1 or later) (.dmg) Intel Mac (.dmg)
First install — allow it once in security settings
  1. Open the DMG and drag Ontological Studio to Applications.
  2. Open the app. When macOS says “Apple could not verify ‘Ontological Studio’ is free of malware…”, click Done.
  3. Open System Settings → Privacy & Security, click Open Anyway next to Ontological Studio in the Security section near the bottom, and enter your password.
  4. In the dialog that appears, click Open. From then on the app opens normally.

The build is not notarized by Apple yet, so this is needed only the first time. On macOS 14 and earlier, you can also right-click the app and choose Open. The Intel Mac build is 0.1.1 (0.1.2 is on its way). Details: Install guide

Windows

Windows 10/11 (x64) · Run the installer.

Download for Windows (.exe)
First install — allow it once in SmartScreen
  1. Run the installer you downloaded.
  2. When “Windows protected your PC” appears, click More info, then Run anyway.
  3. Choose where to install and finish. No administrator rights needed.

You see this because the build is not code-signed yet. The Windows build includes the PostgreSQL connector only for now, and Claude Code needs Git for Windows. Details: Install guide

Agent features (building, asking, making apps) use the Claude Code or Codex CLI installed and signed in on this computer.
The first launch takes 1–2 minutes to prepare the database and seed the samples. After that, it starts in seconds.
Recommended: 16 GB of memory or more, 2 GB of free disk space or more.

Related Solutions

A Knowledge Graph Never Works Alone

Ontological Studio is the design tool that makes an organization’s knowledge explicit as a graph. Its output runs on the execution server of Ontologic Platform for analysis and automation, becomes, via MCP, the knowledge graph that Process GPT agents consult while doing their work, and gives the design and implementation agents of Robo Architect the grounding to understand the domain.

① Ontologic Platform

Design in Studio, execute on the Ontologic server

Ontological Studio works as the ontology design module of Ontologic Platform. The schema Studio creates (classes, relationships, join keys) and its data source mappings connect directly to the Ontologic execution server, where natural-language queries, root-cause analysis, What-if simulation and watch automation run.

Because design and execution share the same ontology, a schema fix is reflected in execution results right away, and the zero-copy binding carries straight through, so operational data is analysed with no separate ETL (Zero-ETL).

Studio schema design → reflected directly on the Ontologic execution server
Shared data source mappings (virtual binding) keep it Zero-ETL
Natural-language queries, root-cause analysis, What-if, and watch automation on the execution server

The most powerful combination

② Process GPT

The knowledge graph that agentic AI consults

The built ontology is exposed as an MCP server, and Process GPT deep agents, while carrying out their work, use ontology_query to explore this knowledge graph in real time. They cite regulatory clauses and operational data together, and decide only on the basis of knowledge made explicit in the ontology, completing hallucination-free business automation.

In an AI-Native Enterprise where AI agents decide and act on their own, what is most lacking is not model performance but “what to base decisions on.” The ontology states that grounding in the organization's own language, and Process GPT executes real work on top of it. This combination, where designed knowledge is executed directly, is the most powerful scenario.

Real-time knowledge exploration via MCP (ontology_query) during process execution
Hallucination-free decisions citing regulatory clauses and operational data together
A virtuous knowledge cycle: sources → knowledge graph → agent execution

③ Robo Architect

A knowledge graph that carries through to design and implementation

The domain knowledge graph built by Ontological Studio becomes the knowledge graph consulted by the design and implementation agents of Robo Architect. Concepts and relationships extracted from documents and operational data ground the design of Aggregates and domain events, so the AI generates code with an accurate understanding of the domain.

The two products exchange knowledge and models freely — Ontological Studio’s knowledge flows into Robo Architect’s specifications, and the models Robo Architect designs accumulate back into the graph. Knowledge and specifications circulate as one flow.

Knowledge graph → the knowledge graph of the design and implementation agents
Concepts and relationships from documents and DBs serve as grounding for domain design
Two-way cycle that accumulates design models back into the ontology
