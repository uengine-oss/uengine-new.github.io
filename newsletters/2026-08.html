NEW FEATURE
한 번 배운 업무는, 매번 정확하게 — Process GPT ‘Deterministic Replay’
AI 에이전트를 실무에 맡기지 못하는 가장 큰 이유는 “같은 일을 시켜도 매번 다르게 한다”는 점이었습니다. Process GPT는 1차 실행에서 에이전트가 호출한 MCP 도구 이력을 이벤트로 기록하고, 검증된 실행 경로를 파라미터화된 Python 코드로 고착합니다. 2차 실행부터는 LLM 추론 없이 그 코드가 그대로 돌아 경로를 100% 재현하고, 보상(undo) 코드까지 자동 생성돼 되돌리기도 안전합니다. E2E 검증 21/21 PASS로 확인했습니다.

PRODUCT
한 곳에 답이 없는 질문에 답하다 — Ontology Studio, 이제 사내 DB까지 하나의 그래프로
현업의 질문은 대개 문서 한 곳에도, 테이블 한 곳에도 답이 없습니다. Ontology Studio가 문서에 더해 MySQL·PostgreSQL 등 7가지 데이터소스를 직접 연결해, 문서의 조항과 데이터베이스의 레코드를 하나의 지식 그래프 위에서 함께 탐색하도록 확장됐습니다. 핵심은 데이터를 옮기지 않는다는 점입니다 — DB는 복제 0건의 virtual 바인딩으로 붙어 별도 ETL이나 데이터 웨어하우스 구축이 필요 없습니다. 스토어드 프로시저의 주석·계산식까지 해석해 컬럼의 의미를 잡아내고, 관계마다 조인 키를 명시해 추측을 없앴습니다. 답변에는 사용한 조회 경로가 근거로 함께 제시되며, 맞다/틀리다 피드백으로 스키마를 보강해 다시 구축하는 자가 개선 루프까지 돕니다.

NEW FEATURE
데이터에서 프로세스까지, 네 개의 층으로 — 에이전틱 스택을 그림 한 장으로
“에이전틱 AI를 도입한다”는 말이 실제로 무엇을 쌓는 일인지, 홈 화면과 AI-Native Enterprise 비전 페이지에 4계층 스택 다이어그램으로 정리했습니다. 사내 DB·문서·외부 API를 표준 인터페이스로 잇는 데이터 연동, 실행 결과를 엔터티·관계로 축적하는 지식 그래프/온톨로지, LangChain·CrewAI와 MCP·A2A 위에서 협업하는 멀티 에이전트, 그리고 목표를 태스크와 분기로 자동 설계해 실행 순서를 조율하는 에이전틱 비즈니스 프로세스 관리까지 — 스크롤에 따라 한 층씩 쌓이며 층 사이로 데이터가 흐르는 모습을 직접 보실 수 있습니다.

코드와 DB를 하나의 그래프로, 근거는 원문까지 — Robo Analyzer 페이지 공개
7월호에서 소개했던 레거시 분석 제품이 Robo Analyzer로 이름을 정리하고 전용 페이지를 열었습니다. 레거시 소스 코드와 데이터베이스 스키마를 함께 분석해 함수 호출과 테이블·컬럼 읽기/쓰기 관계를 하나의 그래프로 보여주고, 자연어로 물으면 관련 로직을 찾아줍니다. 어느 지점에서든 판단의 근거가 된 실제 코드 원문까지 되짚어 볼 수 있어, 분석 결과를 그대로 신뢰하고 다음 단계로 넘길 수 있습니다.

MSA 특집
왜 마이크로서비스는 어려운가 — ‘MSA Architecture’ 메뉴를 새로 열었습니다
마이크로서비스의 어려움은 기술이 아니라 설계에서 옵니다. 새 플래그십 글에서 수다쟁이 마이크로서비스(잘못된 경계), 갓테이블, 사라진 트랜잭션이라는 세 가지 함정을 짚고 응집도·결합도, 데이터 지역성, 어그리게이트와 이벤추얼 컨시스턴시라는 처방을 정부24 클라우드 네이티브 전환 사례와 함께 정리했습니다. 함께 연 CNA/MSA Consulting 페이지에서는 전자정부 표준프레임워크 기반의 설계→구현→배포·운영 3단계 컨설팅과, MSA School 플랫폼에서 운영되는 정규 교육 과정·공개 세미나를 확인하실 수 있습니다. 진단은 Robo Analyzer, 구현은 Robo Architect가 받쳐주는 구성입니다.

INSIGHT
1인 창업자를 위한 AI 시대의 오픈소스 생존 전략
2026 오픈소스 개발자대회 오리엔테이션 특별강연을 글로 정리했습니다. 2003년 공모대전 대상에서 출발한 오픈소스 기업 23년의 기록을 따라가며, 코드를 공개하고도 사업이 굴러가게 만드는 구조를 짚습니다. 핵심은 ‘신뢰 퍼널’ — 제품이 아니라 운영의 위험을 유료화하는 전략입니다. AI가 코드 생산 비용을 끌어내린 시대에 1인 창업자와 소규모 팀이 무엇을 열고 무엇을 남겨야 하는지, 실제 사례로 정리했습니다.
