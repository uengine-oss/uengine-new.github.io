Spec-Driven Development

Robo Architect

명세(Spec)를 중심에 두는 AI 소프트웨어 설계·구현 자동화 플랫폼

다운로드 튜토리얼 데모 영상 보기 제품소개서(PDF) 다운로드

데스크톱 앱 Robo Architect Lite · macOS (Apple Silicon) · Windows (x64) · 설치 안내 · 따라 하는 튜토리얼 15장 · GitHub

Spec-Driven Development(SDD) 기반 AI 소프트웨어 설계·구현 자동화

Robo Architect는 코드가 아닌 명세(Spec)를 중심에 두는 Spec-Driven Development 도구입니다. 자연어 요구사항에서 시작해 영향도 분석 → 샌드박스 구현 → 검증 → 반영으로 이어지는 프로포절(Proposal) 라이프사이클을 통해 명세와 구현을 항상 일치시키며 소프트웨어의 변경을 관리합니다.

DDD(도메인 주도 설계)로 문제 영역을 모델링하고 BDD(행위 주도 개발)의 인수 조건으로 검증하여, 기획자·아키텍트·개발자가 하나의 명세 위에서 협업하고 Claude Code 스킬 엔진이 검증된 코드를 자동으로 생성합니다.

HOW ROBO ARCHITECT WORKS

업무의 의도를 설계하고, 코드까지 연결합니다

기존 시스템의 지식과 새로운 요구사항을 하나의 명세로 정리합니다. Robo Architect는 이 명세를 도메인·화면·구현 작업으로 구체화하고, 변경된 코드와 다시 맞춰 갑니다.

전체 흐름설계와 구현이벤트와 화면명세와 코드
01 / WORKFLOW

지식에서 시작해, 검증된 구현으로

레거시가 있으면 Robo Analyzer가 기존의 업무 규칙을 추출합니다. 신규 개발은 요구사항에서 바로 시작하고, 이후의 설계와 검증은 같은 흐름을 따릅니다.

02 / DOMAIN DESIGN

업무 경계에 맞춰 구현할 단위를 만듭니다

바운디드 컨텍스트는 용어와 규칙이 일관되게 적용되는 업무 경계입니다. 핵심 업무의 복잡도와 지원 업무의 성격에 따라 설계 방식을 구분하고, 각 경계 안에서 구현할 작업을 준비합니다.

CORE DOMAIN

핵심 도메인

업무 규칙이 경쟁력이 되는 영역. 엔티티와 유스케이스를 중심에 두고, 외부 UI·DB의 변화로부터 도메인 로직을 분리합니다.

UI · DB · FrameworksUse CasesDomain Model
SUPPORTING DOMAIN

지원 도메인

정형화된 관리 업무. 표준 계층 구조와 트랜잭션 스크립트, 템플릿을 활용해 필요한 복잡도로 구현합니다.

PresentationTransaction ScriptData Access
03 / EVENT MODELING & UI

사용자 행동과 업무 결과를 화면까지 추적합니다

화면을 따로 그린 뒤 로직을 끼워 맞추지 않습니다. 누가 어떤 지시를 내리고, 어떤 사실이 발생하며, 사용자가 무엇을 보게 되는지를 같은 흐름에 놓습니다.

이벤트 모델은 UI/UX 설계의 연결 기준입니다. Figma 등의 와이어프레임에서 바뀐 입력·출력도 같은 모델과 대조해, 화면과 도메인 설계의 불일치를 줄입니다.

04 / CONTINUOUS ALIGNMENT

명세와 코드가 함께 바뀌는 순환 구조

계획대로 코드를 만드는 것과, 개발 중 달라진 코드를 설계에 반영하는 것은 모두 필요합니다. Robo Architect는 두 방향의 변경을 명세와 검증 기준으로 연결합니다.

명세 → 설계 → 구현 → 검증 → 명세. 다음 변경도 같은 기준 위에서 이어집니다.

주요 기능

자연어 요구사항으로 시작

기획자가 "음식 배달앱으로 음식을 주문하고 메뉴를 관리한다"처럼 요구사항을 자연어로 입력하면 AI가 분석을 시작합니다. 코드가 아닌 요구사항 명세(Spec)에서 모든 것이 출발합니다.

BDD 인수 조건 기반 명세

각 User Story는 Given-When-Then 형식의 인수 조건(Acceptance Criteria)으로 구체화됩니다. 행위 주도 개발(BDD)의 명세가 그대로 검증 기준이 되어 요구사항과 구현의 일치를 보장합니다.

계획을 세우기 전에 설계 원칙·기술 스택·아키텍처 스타일·레포 전략을 헌장(Constitution)으로 한 번 정합니다. Claude Code가 프로포절을 읽고 질문과 추천을 내면 답만 고르면 되고, 이후 Plan의 결정마다 근거가 된 헌장 구절이 붙습니다.

레거시 분석을 근거로 신규 설계

운영 중인 레거시 시스템(Java·DDL)을 분석해 코드 그래프·비즈니스 규칙·데이터 스키마를 만들고, 새 프로포절이 그 분석을 근거로 설계합니다. 레거시의 규칙과 테이블이 신규 서비스의 인수 조건과 데이터 구조로 이어집니다.

코드 그래프·비즈니스 규칙 추출
테이블·컬럼 데이터 스키마
레거시 근거가 붙은 프로포절

데이터 패브릭으로 운영 DB 연결

운영 중인 DB(PostgreSQL·MySQL·MariaDB)를 데이터 소스로 등록하면 실제 테이블이 바로 보이고, 이 연결이 레거시 분석과 데이터 스키마의 원천이 됩니다. Ontological DB와 데이터 패브릭은 데스크톱 앱과 함께 올라옵니다.

연결 시험 후 데이터 소스 등록
실제 테이블 바로 조회
레거시 분석·데이터 스키마의 원천

요구사항 문서로 설계 시작

요구사항 문서 한 편을 통째로 새 프로포절에 붙여 넣으면, Claude Code가 문서 전체를 바운디드 컨텍스트·기능·유저 스토리·인수 조건·프로세스로 나눕니다. 긴 기획서도 그대로 설계의 출발점이 됩니다.

문서를 통째로 붙여 넣기

애그리거트·커맨드·이벤트와 아키텍처 결정이 헌장 근거와 함께 나옵니다.

5장 보충 · 고객용 MVP 미리 보기

구현하기 전에 Plan을 눌러 볼 수 있는 화면으로 열어, 고객들이 피드백 창에서 함께 고치고 좋아요로 합의합니다.

6장 · 샌드박스에서 구현하기

작업 목록을 만들고, 코드 탭의 Claude Code 셀이 샌드박스 워크트리에서 하나씩 구현합니다.

7장 · 검증하고 수락하기

Ontology Studio 연동

에이전트의 지식지도로 이어집니다

Robo Architect가 설계한 도메인 모델(Aggregate·도메인 이벤트·유비쿼터스 언어)은 Ontology Studio의 지식 그래프로 축적됩니다. 설계와 구현이 쌓일수록 시스템 전체가 하나의 온톨로지(지식지도)가 되고, AI 에이전트는 이 지식지도를 참조해 도메인을 이해하고 더 정확한 변경을 수행합니다.

두 제품은 서로 자유롭게 오갑니다 — Robo Architect의 설계를 Ontology Studio에서 그래프로 탐색하고, Ontology Studio가 문서에서 추출한 도메인 지식을 다시 설계 근거로 역참조합니다. 명세와 지식이 한 궤도에서 순환합니다.

프로포절 라이프사이클

요구사항 한 줄이 검증된 코드가 되기까지, Robo Architect는 다음 흐름으로 동작합니다

1. 프로포절 작성

기획자가 자연어로 요구사항을 입력하면 바운디드 컨텍스트·기능·유저 스토리가 자동으로 도출됩니다.

2. 영향도 분석 & 작업 분해

기존 설계에 대한 영향도를 분석하고 tasks.md로 구현할 작업 목록을 자동 구성합니다.

3. 샌드박스 구현

Git Worktree 샌드박스에서 Claude Code 스킬이 DDD 코드와 테스트를 자동으로 구현합니다.

4. 검증 & Accept

Robo Sync로 검증한 뒤 Accept하면 코드와 설계에 양방향으로 반영됩니다.

왜 Robo Architect 인가

Robo Architect는 유행하는 AI 코드 생성 도구가 아니라, 검증된 소프트웨어 공학 사상 위에 세워진 Spec-Driven Development 플랫폼입니다. 명세(Spec)를 단일 진실 원천(Single Source of Truth)으로 삼아, 도메인 주도 설계(DDD)로 문제를 모델링하고 행위 주도 개발(BDD)로 검증합니다.

DDD · 도메인 주도 설계

비즈니스 복잡성을 Aggregate와 도메인 이벤트로 명확히 경계 짓습니다. AI가 코드를 쏟아내도 도메인 모델이 중심을 잡아주므로, 규모가 커져도 무너지지 않는 구조를 유지합니다.

BDD · 행위 주도 개발

요구사항을 Given-When-Then 인수 조건으로 표현하여 명세가 곧 실행 가능한 테스트가 됩니다. ‘무엇을 만들 것인가’와 ‘제대로 만들었는가’가 하나로 연결되어 AI 구현의 정확성을 자동으로 검증합니다.

SDD · 명세 주도 개발

코드가 아닌 명세가 원본입니다. 명세와 구현이 프로포절 라이프사이클과 양방향 싱크로 항상 일치하므로, 변경 이력·영향도·설계가 흩어지지 않고 한 곳에서 관리됩니다.

그 결과, 빠른 AI 생산성과 엔터프라이즈급 유지보수성을 동시에 얻습니다 — 대규모 클라우드 네이티브 시스템의 핵심 도메인을 벤더 종속 없이 안전하게 진화시킬 수 있습니다.

데스크톱 앱 Robo Architect Lite를 설치하면 그래프 DB(Ontological DB)와 데이터 패브릭, 레거시 분석 서비스가 이 컴퓨터의 Docker 위에 함께 올라옵니다. 프로포절의 분석 · 계획 · 구현은 이 컴퓨터에 로그인해 둔 Claude Code가 맡아 API 키가 필요 없습니다.

macOS (Apple Silicon)

M1 이상 Mac · DMG를 받아 열고 Applications로 끌어다 놓습니다. (칩 확인: 🍎 메뉴 → 이 Mac에 관하여)

Apple Silicon (M1 이상) (.dmg)
처음 설치할 때 — 보안 설정에서 한 번 허용
  1. DMG를 열고 Robo Architect Lite를 Applications로 끌어다 놓습니다.
  2. 앱을 엽니다. “Apple은 ‘Robo Architect Lite’에 … 악성 코드가 없음을 확인할 수 없습니다” 창이 뜨면 완료를 누릅니다.
  3. 시스템 설정 → 개인정보 보호 및 보안을 열고, 아래쪽 보안 항목에서 Robo Architect Lite 옆의 그래도 열기를 누른 뒤 암호를 입력합니다.
  4. 다시 뜨는 창에서 열기를 누릅니다. 다음부터는 바로 열립니다.

Apple 공증 전 빌드라서 처음 한 번만 필요합니다. macOS 14 이하에서는 앱을 우클릭 → 열기로도 됩니다. 자세한 내용: 설치 안내

Windows

Windows 10/11 (x64) · 설치 파일을 실행합니다.

Windows 다운로드 (.exe)
처음 설치할 때 — SmartScreen에서 한 번 허용
  1. 내려받은 설치 파일을 실행합니다.
  2. “Windows의 PC 보호” 창이 뜨면 추가 정보를 누르고 실행을 누릅니다.
  3. 설치 위치를 고르고 설치를 마칩니다. 관리자 권한은 필요 없습니다.
  4. 마지막 화면의 실행 체크는 끄고, 시작 메뉴에서 Robo Architect Lite를 엽니다.

코드 서명 전 빌드라서 나오는 확인입니다. Docker Desktop은 WSL 2 기반(Linux 컨테이너)으로 켜 두고, Claude Code를 쓰려면 Git for Windows가 필요합니다. 자세한 내용: 설치 안내

Docker Desktop을 설치하고 켜 둡니다. 앱이 컨테이너 일곱 개를 직접 올리고 내립니다.
Claude Code를 설치하고 로그인해 둡니다(터미널에서 claude 가 실행되면 됩니다).
첫 실행 때 컨테이너 이미지 일곱 개(약 1.1 GB)를 내려받습니다. 홈 화면에 진행 상황이 보이고, 다음부터는 받지 않습니다.
권장 사양: 메모리 16 GB 이상, 디스크 여유 6 GB 이상.
