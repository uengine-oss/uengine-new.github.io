Spec-Driven Development

Robo Architect

명세(Spec)를 중심에 두는 AI 소프트웨어 설계·구현 자동화 플랫폼

GitHub 데모 영상 보기

Spec-Driven Development(SDD) 기반 AI 소프트웨어 설계·구현 자동화

Robo Architect는 코드가 아닌 명세(Spec)를 중심에 두는 Spec-Driven Development 도구입니다. 자연어 요구사항에서 시작해 영향도 분석 → 샌드박스 구현 → 검증 → 반영으로 이어지는 프로포절(Proposal) 라이프사이클을 통해 명세와 구현을 항상 일치시키며 소프트웨어의 변경을 관리합니다.

DDD(도메인 주도 설계)로 문제 영역을 모델링하고 BDD(행위 주도 개발)의 인수 조건으로 검증하여, 기획자·아키텍트·개발자가 하나의 명세 위에서 협업하고 Claude Code 스킬 엔진이 검증된 코드를 자동으로 생성합니다.

주요 기능

자연어 요구사항으로 시작

기획자가 "음식 배달앱으로 음식을 주문하고 메뉴를 관리한다"처럼 요구사항을 자연어로 입력하면 AI가 분석을 시작합니다. 코드가 아닌 요구사항 명세(Spec)에서 모든 것이 출발합니다.

자연어 요구사항 입력
문서 업로드로도 시작 가능
AI 분석 자동 시작

프로포절 기반 변경 관리

입력한 요구사항으로부터 Epic·Feature·User Story(전략적 변경)와 Aggregate·Command·Event(전술적 변경)가 자동 도출됩니다. 모든 변경은 하나의 프로포절로 관리되어 이력을 추적합니다.

전략적·전술적 Diff 자동 생성
Epic/Feature/Story 자동 도출
변경 이력 추적 및 관리

변경 영향도 분석 (Impact Map)

새 요구사항이 기존 설계에 미치는 영향을 Requirements·Process·Design 관점으로 자동 분석합니다. 무엇이 신규이고 무엇이 바뀌는지 Impact Map으로 한눈에 파악합니다.

Requirements·Process·Design 영향 분석
신규/변경 요소 자동 식별
Impact Map 시각화

BDD 인수 조건 기반 명세

각 User Story는 Given-When-Then 형식의 인수 조건(Acceptance Criteria)으로 구체화됩니다. 행위 주도 개발(BDD)의 명세가 그대로 검증 기준이 되어 요구사항과 구현의 일치를 보장합니다.

Given-When-Then 인수 조건
명세가 곧 실행 가능한 테스트
요구사항↔구현 일치 보장

프로세스·유저 저니 설계

사용자 여정(User Journey)과 액터·커맨드·이벤트의 상호작용(Interactions)을 프로세스로 시각화합니다. 비즈니스 흐름을 도메인 이벤트 관점에서 명확하게 표현합니다.

User Journey 시각화
액터·커맨드·이벤트 흐름
비즈니스 프로세스 모델링

Aggregate·이벤트스토밍 설계

DDD에 입각한 Aggregate·Entity·Value Object·Enum 설계와 이벤트스토밍 모델을 자동으로 구성합니다. Bounded Context 단위로 도메인을 명확히 분리하여 복잡성을 다스립니다.

Aggregate·VO·Enum 설계 뷰
이벤트스토밍 모델링
Bounded Context 분리

샌드박스 워크트리 격리 구현

프로포절마다 별도의 Git Worktree(로컬 브랜치) 샌드박스를 만들어 본체 프로젝트에 영향 없이 안전하게 구현합니다. tasks.md로 구현 작업 목록을 자동 분해합니다.

프로포절별 Git Worktree 샌드박스
본체 프로젝트 무영향 안전 구현
tasks.md 작업 자동 분해

Claude Code 스킬 기반 엔진

자체 LangChain/LangGraph가 아닌 Claude Code의 Skill을 호출하여 동작합니다. UI 없이 Claude Code 터미널에서도 그대로 사용할 수 있어 도구에 종속되지 않습니다.

Claude Code Skill 호출 엔진
UI 없이 터미널에서도 동작
표준 에이전트 재사용

오픈 스킬 파일 커스터마이징

엔진의 모든 동작이 편집 가능한 스킬 파일(SKILL.md)로 구성되어 있습니다. 스킬을 바꾸면 Robo Architect의 엔진 자체가 바뀌며, spec-kit·OpenSpec의 검증된 패턴을 참조합니다.

편집 가능한 SKILL.md 엔진
스킬 교체로 동작 변경
spec-kit·OpenSpec 패턴 참조

DDD 기반 코드·테스트 자동 생성

Value Object·Command·Event·Aggregate를 DDD 원칙에 따라 실제 소스 코드로 자동 구현하고 테스트까지 작성합니다. 작업 단위로 커밋하며 진행 상황을 실시간 모니터링합니다.

VO·Command·Event·Aggregate 구현
테스트 코드 자동 작성
작업 단위 커밋·실시간 모니터링

구현 결과 산출물 리포트

Setup·Domain·Application·API·Frontend·Test 단계별 작업과 산출물을 리포트로 정리합니다. 어떤 파일이 생성·변경됐는지, 인수 조건 테스트가 몇 건 통과했는지 명확히 확인합니다.

단계별 작업·산출물 리포트
생성/변경 파일 목록 확인
인수 조건 테스트 결과 집계

검증 & Accept 양방향 싱크

구현체가 스펙대로 만들어졌는지 Robo Sync 스킬로 구조 검증(스펙↔구현체)과 인수 조건(GWT)을 실행합니다. Accept하면 코드가 메인에 머지되는 동시에 설계에 양방향으로 반영됩니다.

Robo Sync 구조·인수 조건 검증
코드↔설계 양방향 싱크
Accept 시 메인 자동 머지

Ontology Studio 연동

에이전트의 지식지도로 이어집니다

Robo Architect가 설계한 도메인 모델(Aggregate·도메인 이벤트·유비쿼터스 언어)은 Ontology Studio의 지식 그래프로 축적됩니다. 설계와 구현이 쌓일수록 시스템 전체가 하나의 온톨로지(지식지도)가 되고, AI 에이전트는 이 지식지도를 참조해 도메인을 이해하고 더 정확한 변경을 수행합니다.

두 제품은 서로 자유롭게 오갑니다 — Robo Architect의 설계를 Ontology Studio에서 그래프로 탐색하고, Ontology Studio가 문서에서 추출한 도메인 지식을 다시 설계 근거로 역참조합니다. 명세와 지식이 한 궤도에서 순환합니다.

설계 도메인 모델 → 지식 그래프(온톨로지)로 축적
AI 에이전트가 지식지도를 참조해 도메인 이해·정확한 변경
문서 기반 도메인 지식을 설계 근거로 역참조 (Neo4j·MCP)
Ontology Studio 살펴보기

프로포절 라이프사이클

요구사항 한 줄이 검증된 코드가 되기까지, Robo Architect는 다음 흐름으로 동작합니다

1. 프로포절 작성

기획자가 자연어로 요구사항을 입력하면 Epic·Feature·User Story가 자동으로 도출됩니다.

2. 영향도 분석 & 작업 분해

기존 설계에 대한 영향도를 분석하고 tasks.md로 구현할 작업 목록을 자동 구성합니다.

3. 샌드박스 구현

Git Worktree 샌드박스에서 Claude Code 스킬이 DDD 코드와 테스트를 자동으로 구현합니다.

4. 검증 & Accept

Robo Sync로 검증한 뒤 Accept하면 코드와 설계에 양방향으로 반영됩니다.

왜 Robo Architect 인가

Robo Architect는 유행하는 AI 코드 생성 도구가 아니라, 검증된 소프트웨어 공학 사상 위에 세워진 Spec-Driven Development 플랫폼입니다. 명세(Spec)를 단일 진실 원천(Single Source of Truth)으로 삼아, 도메인 주도 설계(DDD)로 문제를 모델링하고 행위 주도 개발(BDD)로 검증합니다.

DDD · 도메인 주도 설계

비즈니스 복잡성을 Aggregate와 도메인 이벤트로 명확히 경계 짓습니다. AI가 코드를 쏟아내도 도메인 모델이 중심을 잡아주므로, 규모가 커져도 무너지지 않는 구조를 유지합니다.

BDD · 행위 주도 개발

요구사항을 Given-When-Then 인수 조건으로 표현하여 명세가 곧 실행 가능한 테스트가 됩니다. ‘무엇을 만들 것인가’와 ‘제대로 만들었는가’가 하나로 연결되어 AI 구현의 정확성을 자동으로 검증합니다.

SDD · 명세 주도 개발

코드가 아닌 명세가 원본입니다. 명세와 구현이 프로포절 라이프사이클과 양방향 싱크로 항상 일치하므로, 변경 이력·영향도·설계가 흩어지지 않고 한 곳에서 관리됩니다.

그 결과, 빠른 AI 생산성과 엔터프라이즈급 유지보수성을 동시에 얻습니다 — 대규모 클라우드 네이티브 시스템의 핵심 도메인을 벤더 종속 없이 안전하게 진화시킬 수 있습니다.
