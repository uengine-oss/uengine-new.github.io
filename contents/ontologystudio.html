Our Products

Ontological Studio

온톨로지를 만들고, 묻고, 실행하고, 앱으로 쓰는 데스크톱 스튜디오.
설치 파일 하나에 데이터 패브릭·그래프 DB·에이전트가 모두 들어 있습니다.

macOS 다운로드 Windows 다운로드 데모 영상 보기

macOS (Apple Silicon) · Windows 10/11 (x64) · 오픈소스 · 설치 안내

답은 한 곳에 있지 않고, 일은 답에서 끝나지 않습니다

“납땜 불량이 난 부품은 어느 완제품에 들어가고, 그 협력사 담당자는 누구인가?” — 이런 질문의 답은 품질 보고서와 구매 ERP, 물류 시스템에 흩어져 있습니다. 답을 찾은 다음에는 발주를 멈추고, 선적을 서두르고, 현황을 매일 지켜봐야 합니다.

Ontological Studio는 이 흐름을 한 앱 안에서 잇습니다. 문서와 데이터베이스를 옮기지 않고 연결해 에이전트가 온톨로지를 설계하고, 질문에는 관계를 따라 근거와 함께 답합니다. 지시는 등록된 업무 시스템의 API로 액션이 되어 사람의 승인 뒤에 실행되고, 필요하면 되돌립니다. 그리고 같은 온톨로지 위에서 업무 앱을 말로 만듭니다 — 위젯을 엮는 대시보드로도, 에이전트가 코드를 쓰는 앱으로도.

데모 ① 문서 한 장으로 온톨로지를 만들고, 발행하고, 근거와 함께 답하기까지 (2:56)

데모 ② 골든 커맨드 하나로 액션을 만들고 — 질의 · 승인 · 실행 · 취소 (2:58)

데모 ③ 온톨로지 앱 — @멘션으로 대시보드를, 에이전트로 코드 앱을 만들기 (3:12)

주요 기능

연결 → 구축 → 발행 → 질의 → 액션 → 앱, 모두 같은 온톨로지 위에서 이어집니다

문서 한 장에서 온톨로지까지

근거로 삼을 문서나 데이터베이스를 고르고, 무엇에 답해야 하는지(구축 의도 · Golden Question)를 적습니다. 에이전트가 개념과 관계를 설계하고, 사실을 인스턴스로 옮긴 뒤 Golden Question을 직접 던져 답이 나오는지 검증합니다. 발행은 사람이 정합니다.

구축 의도 · Golden Question 초안을 에이전트가 먼저 제안
클래스 · 관계 설계 → 인스턴스 적재 → 자체 검증
발행한 온톨로지만 질의와 앱에 쓰임

근거가 남는 질의

무엇을 어떤 순서로 찾으라고 알려 주지 않아도 됩니다. 에이전트는 발행된 지도를 읽고 품질 이슈에서 부품으로, 완제품과 협력사, 담당자로 관계를 따라가 답합니다. 답이 어디서 왔는지가 화면에 남습니다.

그래프 관계를 따라가는 Graph RAG
답마다 근거 노드·관계 표시
MCP 로 다른 AI 에이전트에도 제공

복제 없는 데이터 패브릭

PostgreSQL · MySQL/MariaDB · Oracle · SQL Server 를 접속 정보만으로 연결하고, 테이블을 가상 노드로 노출합니다. 데이터를 옮기지 않고 질의하는 순간 원천에서 읽기 때문에, 서로 다른 엔진의 데이터베이스를 하나의 Cypher 로 가로질러 묻습니다.

연결 · 테이블 미리보기 · 가상 노드 · 가상 관계를 한 화면에서
교차 DB Cypher 실측 약 140 ms, 한글 그대로
원천은 읽기 전용 — 쓰기는 액션으로만

Golden Command → 액션

이 온톨로지로 할 수 있어야 할 지시를 Golden Command 로 적어 두면, 에이전트가 등록된 업무 시스템의 API 를 살펴 액션과 되돌리는 보상, 쓸 수 있는 사람과 대상을 정하는 정책을 만들고 드라이런으로 검증합니다. 실행은 언제나 사람의 승인 뒤입니다.

계획 → 승인 → 실행(saga) → 취소 시 보상
예제 시스템 3종(구매 ERP · 물류 WMS · 고객 CRM) 내장
결과는 데이터소스 화면에서 원천 테이블로 확인

@멘션으로 만드는 대시보드

입력창에서 @ 로 클래스·속성을 부르거나 자원 트리에서 끌어다 놓아 만들고 싶은 화면을 적습니다. 멘션한 클래스는 엔진이 데이터를 살펴 위젯을 바로 정하고(약 1초), 나머지 요청은 에이전트가 구성안(diff)으로 냅니다. 적용은 사람이 누릅니다.

클래스 · 속성 · 위젯을 문장 안의 칩으로
Golden Question 이 예시로 붙음
낮/밤 테마를 차트까지 따름

에이전트가 코드를 쓰는 코드 앱

같은 입력창에서 「코드 앱」을 고르면 코딩 에이전트(Claude Code · Codex)가 온톨로지에 질의를 직접 시험한 뒤 앱 코드를 씁니다. 왼쪽에는 시험한 질의와 쓴 파일이 흐르고, 오른쪽 미리보기는 파일이 바뀔 때마다 다시 뜹니다. 고칠 점은 말로 이어서 하면 같은 세션이 고칩니다.

Vue 앱 코드(HTML · JavaScript · CSS) — 빌드 없이 바로 실행
데이터는 읽기 전용 질의 SDK 로만
앱 탭으로 열어 업무 화면처럼 사용

Ontological Portal

그래프를 직접 다루는 콘솔입니다. 질의 칸에 Cypher 대신 말로 쓰면 에이전트가 스키마를 보고 Cypher 로 바꿔 한 번 시험해 본 뒤 실행합니다. Cypher 를 직접 칠 때는 라벨·관계·속성 자동완성과 구문 색이 붙습니다.

자연어 → Cypher (실패하면 엔진 메시지로 한 번 고침)
라벨 · 관계 타입 · 속성 자동완성
스키마 지도 · 시점 조회

동작 방식

사람은 무엇을 원하는지 말하고 결정합니다. 설계·질의·코드는 에이전트가, 실행은 승인 뒤의 실행기가 맡습니다.

1. 연결

문서를 올리거나 원천 DB·업무 시스템을 등록합니다. 데이터는 옮기지 않습니다.

2. 구축

구축 의도와 Golden Question·Command 를 기준으로 에이전트가 온톨로지를 설계하고 검증합니다.

3. 발행

사람이 확인하고 발행합니다. 발행된 온톨로지만 질의·액션·앱에 쓰입니다.

4. 질의

말로 물으면 관계를 따라 근거와 함께 답합니다. 포털에서는 Cypher 로 직접.

5. 액션

지시는 계획이 되고, 승인 뒤 업무 시스템 API 로 실행됩니다. 취소하면 보상 단계가 되돌립니다.

6. 앱

같은 온톨로지 위에서 대시보드를 엮거나, 에이전트에게 앱 코드를 맡깁니다.

설치 파일 하나에 들어 있는 것

Docker도 Neo4j도 따로 띄우지 않습니다. 앱이 켜지면 아래가 이 PC 안에서 함께 뜨고, 끄면 함께 내려갑니다.

연관 솔루션

지식지도는 혼자 쓰이지 않습니다

Ontology Studio는 조직의 지식을 그래프로 명시화하는 설계 도구입니다. 그 산출물은 Ontologic Platform의 실행 서버에 실려 분석·자동화가 되고, MCP를 통해 Process GPT의 에이전트가 업무 중 참조하는 지식지도가 되며, Robo Architect의 설계·구현 에이전트에게는 도메인 이해의 근거가 됩니다.

① Ontologic Platform

설계는 Studio에서, 실행은 Ontologic 서버에서

Ontology Studio는 Ontologic Platform의 온톨로지 설계 모듈로 맞물립니다. Studio가 만든 스키마(클래스·관계·조인 키)와 데이터소스 매핑이 그대로 Ontologic 실행 서버에 연결되고, 그 위에서 자연어 질의·원인 분석·What-if 시뮬레이션·감시 자동화가 수행됩니다.

설계와 실행이 같은 온톨로지를 공유하므로 스키마를 고치면 실행 결과가 곧바로 따라오고, 무복제 바인딩이 그대로 이어져 별도 ETL 없이(Zero-ETL) 운영 데이터 위에서 분석이 돕니다.

Studio의 스키마 설계 → Ontologic 실행 서버에 그대로 반영
데이터소스 매핑(virtual 바인딩)을 공유해 Zero-ETL 유지
실행 서버에서 자연어 질의·원인 분석·What-if·감시 자동화

② Process GPT

Agentic AI가 참조하는 지식지도

구축된 온톨로지는 MCP 서버로 노출되고, Process GPT의 딥 에이전트는 업무를 수행하는 도중 ontology_query로 이 지식지도를 실시간으로 탐색합니다. 규정 조항과 운영 데이터를 함께 인용하고, 온톨로지에 명시된 지식에 기반해서만 판단하므로 환각 없는 업무 자동화가 완성됩니다.

AI 에이전트가 스스로 판단해 일하는 AI-Native Enterprise에서 가장 부족한 것은 모델의 성능이 아니라 “무엇에 근거해 판단할 것인가”입니다. 온톨로지는 그 근거를 조직의 언어로 명시해 주고, Process GPT는 그 위에서 실제 업무를 실행합니다. 설계된 지식이 곧바로 실행되는 이 조합이 가장 강력한 시나리오입니다.

프로세스 실행 중 MCP(ontology_query)로 실시간 지식 탐색
규정 조항과 운영 데이터를 함께 인용한 환각 없는 판단
소스 → 지식그래프 → 에이전트 실행의 지식 선순환
Process GPT 자세히 보기 연동 데모 영상보기

③ Robo Architect

설계와 구현으로 이어지는 지식지도

Ontology Studio가 구축한 도메인 지식 그래프는 Robo Architect의 설계·구현 에이전트가 참조하는 지식지도가 됩니다. 문서와 운영 데이터에서 추출한 개념과 관계가 Aggregate·도메인 이벤트 설계의 근거가 되어, AI가 도메인을 정확히 이해한 채 코드를 생성합니다.

두 제품은 서로 자유롭게 오갑니다 — Ontology Studio의 지식을 Robo Architect의 명세로 잇고, Robo Architect가 설계한 모델을 다시 그래프로 축적합니다. 지식과 명세가 한 궤도에서 순환합니다.

지식 그래프 → 설계·구현 에이전트의 지식지도

개인정보 수집 및 이용

유엔진솔루션즈(이하 "회사")가 문의하신 내용에 대한 답변을 제공하기 위해 개인정보를 수집·이용하고자 하는 경우에는 ｢개인정보 보호법｣등 관계 법령에 따라 본인의 동의가 필요합니다.
회사 제품 구매 및 컨설팅 문의 응답, 회사가 제공하는 서비스 이용과정을 위한 최소한의 개인정보를 수집하고 이용합니다.
수집된 정보는 발송 외 다른 목적으로 이용되지 않으며, 서비스가 종료될 경우 즉시 파기됩니다.

유엔진솔루션즈는 2003년 이래 업무 프로세스 관리 (Business Process Management), AI, MSA, 기업용 SNS, PaaS 를 포함한 클라우드 플랫폼, 도메인 기반 개발 방법을 지향하는 개발 프레임워크 등을 개발하고 오픈소스 프로젝트로 제공하는 기술 집약적 기업입니다.
