Industry Solutions · ERP

uEngine ERP

판매 하나로 시작해 회사가 성장하는 만큼 재고, 구매, 청구, 회계를 더하는 이벤트 소싱 ERP

앱 열기튜토리얼시연 영상

오픈소스(MIT)입니다. 데이터는 내 Supabase 프로젝트에 두고, 앱은 정적 파일이라 따로 운영할 서버가 없습니다. 메일 발송과 전자세금계산서, 은행 자동 연결은 포함하지 않습니다. 영상과 예측 수치는 모두 가상 회사의 결과입니다.

모든 변경을 이벤트로 쌓는 ERP

값을 덮어쓰지 않고 일어난 일을 그대로 쌓습니다. 어떤 과거 시점이든 그때 그대로 볼 수 있고, 잘못 처리한 작업은 범위를 확인한 뒤 되돌릴 수 있으며, 쌓인 이력으로 바꾸기 전에 결과를 시험할 수 있습니다.

모듈끼리는 이벤트로만 연결됩니다. 따라서 판매만 쓰다가 필요할 때 재고를 켜도 판매 모듈은 달라지지 않고, 한 모듈이 멈춰도 다른 모듈은 계속 동작합니다.

회사가 성장하는 만큼 더합니다

실제 앱을 실행해 찍은 화면입니다. 데이터는 가상 회사 가온가전의 것입니다.

모듈

필요할 때 하나씩 켭니다

처음에는 판매만 켜져 있습니다. 어떤 조합으로도 동작하고, 켜면 메뉴와 쓸 수 있는 예측이 함께 늘어납니다.

  • 장애 격리재고 모듈이 멈춰도 주문은 계속 받고, 복구되면 밀린 이벤트를 누락 없이 처리합니다.
  • 나중에 켜기회계를 나중에 켜도 지난 청구와 입금으로 전표를 다시 만듭니다. 켜기 전의 재고처럼 알 수 없는 것은 알 수 없다고 알려 줍니다.
  • 플러그인SQL 파일 하나로 모듈을 더합니다. 기존 모듈을 고치지 않습니다.
▶ 2장 재고 켜기와 장애 격리

업무

견적부터 입금까지, 발주부터 지급까지

견적, 주문, 출고, 재주문, 구매, 입고, 청구, 입금, 분개가 이벤트로 이어집니다.

  • 재고창고, 입출고, 재고 조정, 재주문 규칙, 평균 원가.
  • 청구와 회계청구서, 대변 메모, 입금, 시산표, 손익, 재무상태, 세금 집계, 기간 잠금.
  • 은행명세서를 파일로 가져와 입금과 맞춰 봅니다. 은행 자동 연결은 없습니다.
▶ 1장 판매로 시작하기▶ 3장 구매·청구·회계

시간 여행

그때 그대로 보고, 범위를 확인하고 되돌립니다

날짜를 고르면 그 시점의 주문, 재고, 미수금이 그대로 보입니다. 되돌리기는 기존 이벤트를 지우지 않고 이벤트를 하나 더 남깁니다.

  • 연쇄 미리보기주문을 되돌릴 때 함께 되돌아갈 출고와 재고를 다른 모듈까지 확인해 먼저 보여 줍니다.
  • 막아야 할 것은 막습니다게시된 청구서가 관련되어 있으면 되돌리기를 막고 대변 메모를 안내합니다. 잠금일 이전의 되돌리기도 막습니다.
  • 사유와 이력누가 왜 되돌렸는지 원장에 남고, 되돌리기도 다시 되돌릴 수 있습니다.
▶ 4장 시간 여행과 되돌리기

예측과 what-if

바꾸기 전에 시험합니다

발주량, 단종, 창고 재배치, 납기, 결제 조건을 바꾸면 매출과 품절이 어떻게 달라지는지 80% 구간으로 보여 줍니다. 원장은 바뀌지 않습니다.

  • 근거가 없으면 숫자를 내지 않습니다모델마다 잠김, 근거 부족, 사용 가능 중 하나로 표시합니다.
  • 구분할 수 없으면 그렇게 말합니다구간이 0을 포함하면 효과를 구분할 수 없다고 먼저 말합니다.
  • 모듈이 늘면 예측과 시험 범위도 늘어납니다판매만으로는 통계와 수요 예측을 사용할 수 있고, 재고를 켜면 발주 시험, 구매를 켜면 납기 시험을 할 수 있습니다.
▶ 5장 예측과 what-if

연동

REST와 MCP를 따로 만들지 않습니다

유형을 정의하면 REST 자원이 생기고, 에이전트는 도구 4개로 켜져 있는 모듈의 문서를 다룹니다. 별도 서버 프로세스가 없습니다.

  • REST표준 CRUD, 버전 확인, 재시도 키.
  • MCP조회·생성·수정·삭제 MCP 도구 4개로 문서를 다루며, 문서의 상태 변경이 곧 업무 동작입니다. 에이전트는 자기가 MCP로 한 일에 다른 작업이 이어지지 않았을 때 같은 도구로 자기 실수를 되돌립니다.
  • 연동 키구성원 권한을 넘지 못하며, 언제든 폐기할 수 있습니다. 키는 해시로만 저장합니다.
▶ 6장 플러그인과 외부 연동

구성과 현재 상태

구현된 기능과 아직 구현되지 않은 기능을 그대로 적었습니다.

구분내용
앱 공개앱과 소스 저장소를 공개했습니다. 실제 Supabase 클라우드 설치는 아직 시험하지 않았습니다. 막히면 문의하세요.
모듈판매, 재고, 구매, 청구, 회계, 세금 신고, 고정자산, 인사, 휴가, 근태, 급여, 제조, 경비, CRM, 프로젝트 15개를 제공합니다. 모듈별로 켜고 끌 수 있습니다. 판매·재고·구매·청구·회계 32개 조합과 나머지 모듈을 더한 조합을 시험합니다. 급여·휴가·근태·경비는 인사, 제조는 재고를 켜야 사용 가능합니다. 경비는 본인, 승인자, 대신 올린 사람, 회계, 관리자만 읽습니다.
기본 기능 범위다섯 모듈 시점에 주요 ERP의 기본 기능 256개 항목과 대조했습니다. 226개 제공, 22개 일부, 3개 없음, 5개는 메일 서버가 필요합니다. 고급 기능은 주문 처리에 필요한 것만 넣었습니다. 이후 추가한 모듈은 대조표에 포함하지 않았습니다.
없는 것메일 발송, 전자세금계산서 발행(승인번호만 기록합니다), 은행 자동 연결, 외화 환산(외화 입력은 거부합니다), XML 가져오기, 청구서 PDF 첨부는 제공하지 않습니다. 회계·세금·급여·노동 화면은 전문가 검수 전입니다.
시험SQL 1,273개, HTTP 17개, 브라우저 277개 시험을 로컬 Supabase에서 모두 통과했습니다. 실제 Supabase 클라우드에서는 아직 측정하지 않았습니다.
용량무료 플랜 500 MB에 이벤트 약 13만 건, 주문 약 1만 건이 들어갑니다(다섯 모듈을 모두 켠 기준). 하루 주문 10건이면 약 3년입니다. 나머지 모듈을 켠 경우는 아직 측정하지 않았습니다.
예측의 정확도정답을 아는 가상 회사로 측정했습니다. 품절이 잦은 회사에서는 발주와 단종 what-if가 판매 이력만 쓴 것보다 정확도가 크게 높았지만, 재고가 넉넉한 회사에서는 차이가 작고, 창고 재배치는 대부분 구분할 수 없다고 답합니다. 실제 회사에서는 더 나쁠 수 있습니다.
모듈 사이 지연모듈은 이벤트로 이어지므로 주문 확정과 출고 전표 사이에 짧은 지연이 있습니다. 모듈마다 따로 확장할 수는 없습니다.
MCPProcess GPT Lite에 실제로 연결해 가상 회사·로컬 환경에서 세금계산서 처리, 말로 취소(사가 보상), 내년 분기 전망, what-if 질문을 실제 LLM과 실제 MCP로 실행해 확인했습니다.
MCP 되돌리기에이전트는 자기가 MCP로 한 일에 다른 작업이 이어지지 않았을 때만 되돌리며, 연동 키는 묶인 구성원의 권한을 넘지 못합니다. 그 밖에는 관리자가 처리하고, 다른 작업이 이어졌다면 함께 돌아갈 작업을 확인하고 동의해야 실행됩니다.

영상으로 보기

실제 앱을 실행하며 녹화한 영상입니다. 데이터와 수치는 가상 회사의 것입니다. 썸네일을 누르면 재생됩니다.

제품 소개

제품 소개

모듈 켜기, 시간 여행, 되돌리기, what-if를 한 번에 봅니다.

Process GPT Lite와 함께

세금계산서 전표 처리와 취소

파일을 올리면 묻고, 수락하면 MCP로 처리하고, 말로 취소하면 사가가 보상합니다. 되돌리면 안 될 때는 멈춥니다.

채팅으로 묻는 전망과 what-if

내년 어느 분기에 뭐가 팔릴지, 발주를 늘리면 어떻게 되는지 묻습니다. 숫자는 화면과 같은 모델이 계산합니다.

튜토리얼

1장 판매로 시작하기

설치하고 회사를 만든 뒤, 판매만 켠 상태로 견적과 주문을 처리합니다.

2장 재고 켜기와 장애 격리

재고를 켜면 주문 이벤트로 출고 전표가 생깁니다. 재고가 멈춰도 판매는 계속됩니다.

3장 구매·청구·회계

재주문에서 입고, 청구, 입금, 시산표까지 이어 갑니다. 회계는 나중에 켜도 과거 전표를 다시 만듭니다.

4장 시간 여행과 되돌리기

과거 시점을 그대로 보고, 잘못 처리한 작업이 영향을 미치는 범위를 다른 모듈까지 확인한 뒤 되돌립니다.

5장 예측과 what-if

근거가 있을 때만 숫자를 냅니다. 발주, 단종, 재배치, 납기, 결제 조건을 바꾸기 전에 시험합니다.

6장 플러그인과 외부 연동

SQL 파일 하나로 플러그인을 추가하고, 자동으로 생성된 REST와 도구 4개로 구성된 MCP로 연결합니다.

내 Supabase 프로젝트로 바로 시작하세요

가상 회사 가온가전으로 먼저 체험할 수도 있습니다. 튜토리얼 1장에서 설치부터 안내합니다. 우리 회사에 맞춘 도입이나 AI 에이전트 연결은 문의해 주세요.
