# monthly-newsletter — 최근 변경사항 → 이메일 뉴스레터 HTML 생성

지난 한 달(또는 마지막 발행 이후)의 git 히스토리 + 로컬 미커밋 변경사항을 근거로,
고객에게 발송할 **이메일 호환 HTML 뉴스레터**를 만든다. 사이트 페이지가 아니라
Stibee(`https://uengine.stibee.com/`) 같은 이메일 서비스에 붙여넣는 산출물이므로
`contents/`의 nav/footer 하드코딩 관례를 따르지 않는다 (CLAUDE.md 의 "메뉴 중복" 문제와 무관).

## 입력 (없으면 기본값 사용, 애매하면 확인)
1. **기간** — 기본 오늘 기준 최근 1개월. `newsletters/` 폴더에 이전 호가 있으면
   그 파일명(발행월)부터 오늘까지로 좁히는 것을 우선 고려(중복 게재 방지).
2. **발행월 라벨** — 파일명/제목에 쓸 `YYYY-MM` (기본: 오늘 기준 해당 월).
3. **사이트 베이스 URL** — `https://www.uengine.org/` (CNAME 파일 기준, 하드코딩 가능).

---

## 절차

### 1. 변경 이력 수집
```bash
# 커밋된 변경분 (파일별 A/M/D 상태 포함)
git log --since="<date>" --name-status --pretty=format:'commit:%h|%ad|%s' --date=short

# 로컬 미커밋 변경분 — 반드시 포함한다 ("아직 push는 안 됐지만 이번 호에 실을 내용")
git status --short
git diff --stat
```
커밋 메시지만으로 내용 파악이 안 되면(예: "Update Ontology Studio page") 해당 파일의
실제 diff를 읽는다:
```bash
git show <hash> -- <path>          # 커밋된 변경
git diff -- <path>                 # 미커밋 변경
```
신규 블로그 글처럼 파일 전체가 추가(A)된 경우는 diff 대신 완성된 파일을 `Read`로 읽어
핵심 섹션(리드 문단, 소제목들)을 파악한다.

### 2. 파일 경로 기준 카테고리 분류
| 패턴 | 분류 | 비고 |
|---|---|---|
| `contents/blog/<slug>.html` (신규, status A) | 새 블로그 글 | 리드 문단·핵심 키워드 추출 |
| `contents/bloglist.html` 만 단독 변경 | (블로그 신규 항목에 흡수) | 별도 항목화하지 않음 |
| `contents/<product>.html` + `images/<slug>/*` 또는 `images/full-width-images/main-img-<slug>.png` | 제품 업데이트/신규 출시 | 신규 페이지(A)면 "출시", 수정(M)이면 "업데이트"로 문구 구분 |
| `index.html` 스플래시/메뉴 변경 | 사이트 개편 | 고객에게 중요한 신규 메뉴만 한 줄로. 사소한 라벨 변경은 생략 |
| 동일 패턴이 반복되는 전 페이지 일괄 수정(nav/footer 배치 등) | 노이즈 | 뉴스레터에서 **제외** — 최종 결과물(신규 제품/글)에 이미 반영되어 있음 |
| `.claude/`, `.github/`, `scripts/`, `*.md`(README 등) | 내부 도구/문서 | **제외** — 고객 무관 |
| 같은 페이지를 여러 커밋이 반복 수정 | — | 최종 상태 기준으로 **1개 항목**으로 병합 |

이 표를 기계적으로 따르되, 애매한 파일은 실제 diff 내용을 보고 판단한다.

### 3. 상위 항목 선정 및 카피라이팅
- 전체 커밋을 나열하지 말고, 고객 관점에서 임팩트 있는 **3~6개 항목**만 추린다.
- 항목마다 다음을 작성:
  - **제목**: 제품명/핵심 키워드가 드러나는 클릭 유도형 한 줄 (예: "레거시 코드, 이제 AI가 분석까지 — Robo Legacy Analyzer 공개")
  - **본문 2~3문장**: 무엇이 바뀌었고 고객에게 왜 중요한지. 내부 구현/리팩터링 디테일이 아니라
    사용자가 체감하는 가치 위주로 서술.
  - **대표 이미지** (4번 참고)
  - **CTA 링크**: 실제 사이트 절대 URL
- 헤더에는 발행월 타이틀 + 1~2문장 인트로("이번 달 uEngine은 이런 것들을 새로 만들었습니다" 톤).
- 항목이 하나도 없으면(순수 내부 변경만 있던 달) 사용자에게 알리고 발행 여부를 확인한다 — 억지로 채우지 않는다.

### 4. 이미지 재사용 (신규 제작 금지 — repo에 있는 것만 재사용)
- **제품 페이지**: `images/full-width-images/main-img-<slug>.png` 우선.
- **신규 블로그 글**: 본문 안 첫 번째 콘텐츠 이미지(다이어그램/캡처)를 재사용.
  ```bash
  grep -m1 -o '<img src="[^"]*"' contents/blog/<slug>.html
  ```
  로고/아이콘성 이미지는 건너뛰고 본문 `.prose`/`.blog-item-body` 안의 첫 이미지를 쓴다.
- 마땅한 이미지가 없으면 **이미지 없이 텍스트만** 넣는다 (억지 매칭 금지).
- 이메일 클라이언트는 상대경로를 못 읽으므로 **모든 `<img src>`와 `<a href>`는 절대 URL**로 작성:
  `https://www.uengine.org/images/...`, `https://www.uengine.org/contents/...`.

### 5. 이메일 호환 HTML 작성
- `<table>` 기반 레이아웃, 컨테이너 최대폭 640px, **인라인 `style=""`만** 사용
  (Gmail 등 다수 클라이언트가 `<head><style>` 블록을 제거하므로 외부/내부 스타일시트 의존 금지).
- 웹폰트 대신 시스템 폰트 스택(`Arial, "Apple SD Gothic Neo", sans-serif`).
- 사이트 톤 유지: 헤더 다크 네이비(`#1a1a2e`) 배경 + 로고, 포인트 컬러 보라(`#7c4dbc`) —
  blog 다이어그램(`add-blog-post` 스킬 참고)과 동일 팔레트.
- **헤더 로고**: `https://www.uengine.org/images/logo-w.png` 사용, 실제 원본 비율은
  2170×451(≈4.81:1)이다. 사이트 페이지들은 CSS(`max-height`)로 비율을 유지하지만
  이메일은 인라인 `width`/`height` 속성이 그대로 적용되므로 **반드시 비율을 지켜서 지정**한다
  (예: `width="105" height="22"`). `height="34"`처럼 임의로 늘리면 로고가 찌그러진다 —
  실제로 2026-07호에서 이 실수가 있었다.
- 구조: 헤더(로고 + 발행월 타이틀) → 인트로 한 줄 → 항목 카드 반복(이미지 → 제목 → 본문 →
  "자세히 보기 →" 버튼) → 구분선 → 푸터(회사 정보 + 기존 Stibee 구독 링크 + 문의 이메일).
- 다크모드 대응 불필요(이메일은 라이트 고정 권장).

### 6. 저장 위치
- `newsletters/<YYYY-MM>.html` — 레포 루트에 신규 폴더(사이트 페이지가 아니라 이메일
  발송용 산출물이므로 `contents/`와 분리해 아카이브한다). 폴더가 없으면 새로 만든다.

### 7. 검증
- 본문에 넣은 절대 URL이 실제로 존재하는 페이지/이미지 경로인지 확인:
  ```bash
  grep -o 'uengine.org/[^"]*' newsletters/<YYYY-MM>.html | sed 's#https://www.uengine.org/##' \
    | while read p; do [ -f "$p" ] || echo "MISSING: $p"; done
  ```
- 로컬 브라우저로 렌더 확인:
  ```bash
  open newsletters/<YYYY-MM>.html
  ```
- 커밋은 사용자가 요청할 때만.

## 산출물
- `newsletters/<YYYY-MM>.html` (신규, 이메일 호환 인라인 스타일)

## 체크리스트
- [ ] `git log --since` + `git status`/`git diff`로 커밋분·미커밋분 모두 수집
- [ ] 내부 도구/문서/노이즈(반복 nav 수정 등) 제외, 같은 페이지 중복 커밋은 1개로 병합
- [ ] 상위 3~6개 항목만 선정, 고객 가치 중심 카피라이팅
- [ ] 이미지는 repo 기존 자산만 재사용(제품: main-img-<slug>.png / 블로그: 본문 첫 이미지), 없으면 생략
- [ ] 모든 이미지·링크는 `https://www.uengine.org/...` 절대경로
- [ ] 테이블 레이아웃 + 인라인 style만 사용(이메일 클라이언트 호환)
- [ ] 헤더 로고 `width`/`height`가 원본 비율(2170×451 ≈ 4.81:1)과 일치하는지 확인(찌그러짐 방지)
- [ ] `newsletters/<YYYY-MM>.html`로 저장, 존재하지 않는 경로 없는지 grep 검증
- [ ] 로컬에서 열어 렌더 확인 후 사용자에게 발행 여부 확인 (커밋은 요청 시에만)
