## 오늘 손에 남는 산출물 다섯 가지

오늘 산출물은 다섯 가지입니다. 의도 문서, 요구사항, 이벤트 보드, ERD와 DDL, 그리고 화면입니다. 앞 단계 파일이 다음 단계의 입력이 됩니다. 이 교재의 화면은 모두 실제로 실행한 결과이고, AI 답변 문구는 직접 할 때 조금씩 다를 수 있습니다.

## 기획 단계에 AI를 쓰는 두 가지 방식

기획에 AI를 쓰는 방식은 크게 둘입니다. 프롬프트 한 번에 맡기면 AI가 빈칸을 추측으로 채우고, 그럴듯한 문서 속 누락은 구현한 뒤에야 드러납니다. 오늘은 AI가 모르는 것을 되묻게 하고, 단계마다 사람이 승인하는 방식으로 진행합니다.

**프롬프트 한 번에 맡기기**

- AI가 빈칸을 추측으로 채웁니다
- 문서는 그럴듯한데 누락을 알아채기 어렵습니다
- 구현한 뒤에 다시 만듭니다

**되묻게 하고 사람이 승인하기**

- AI가 모르는 것을 질문합니다
- 문서의 문장마다 근거가 남습니다
- 단계마다 사람이 승인해야 넘어갑니다

오늘은 오른쪽 방식을 인터뷰, 모델링, 화면 세 단계에 차례로 적용합니다.

## 실습 주제: 사내 장비 대여 서비스

실습 주제는 사내 장비 대여 서비스입니다. 가상의 회사를 가정한 짧은 구상 글이고, 빈틈을 그대로 남겼습니다. 문제는 세 가지가 적혀 있는데 무엇이 먼저인지 없습니다. AI가 이 빈틈을 어떻게 찾아내는지 보겠습니다.

brief.md (이 글을 그대로 저장합니다)

직원 300명 규모 회사입니다. 노트북, 빔프로젝터, 카메라, 촬영 조명 같은 공용 장비를 지금은 총무팀이 엑셀과 메신저로 관리합니다. 누가 무엇을 언제까지 빌렸는지 찾기 어렵고, 같은 장비를 두 사람에게 약속하는 일이 한 달에 몇 번씩 생깁니다. 반납이 늦어져도 총무 담당자가 일일이 연락해야 합니다.

웹에서 직원이 장비를 찾아 대여를 신청하고, 총무 담당자가 승인한 뒤 수령과 반납까지 기록되면 좋겠습니다. 반납이 늦으면 자동으로 알려 주면 좋겠습니다.

일부러 짧고 빈틈이 있게 썼습니다. 이 글은 가상의 회사를 가정한 것입니다.

오늘 다루는 도구입니다. 표의 오른쪽 칸이 이 교재에서 실제로 확인한 범위입니다. AI-DLC, ddd-starter, Mermaid, OpenUI, Relume은 끝까지 실행했습니다. ChatPRD, Eraser, Uizard는 가입이 필요해 요금만 확인했고, bolt.diy는 설치까지만 했습니다.

시작 전에 준비를 확인합니다. Claude Code와 로그인된 계정, 브라우저, git은 꼭 필요합니다. 3부의 로컬 실습에는 uv와 Ollama가 필요하고, 모델은 4.7기가바이트라 수업 전에 미리 받아 둡니다. 2부 DDL 실습에는 Docker를 씁니다.

**꼭 필요한 것**

- Claude Code와 로그인된 계정
- Chrome 같은 최신 브라우저
- git

**3부 로컬 실습에 필요한 것**

- uv와 Ollama
- 모델 4.7GB를 내려받을 공간과 시간
- 2부 DDL 실습용 Docker
