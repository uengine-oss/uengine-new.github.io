## Cypher·색인

### GL-02 · 전문 색인을 만들었는데 「없는 색인」이라고 나옵니다 {#gl-02}

관련 장: [4장](cypher-basics.html)

- **증상** `` CREATE FULLTEXT INDEX zz_cjk IF NOT EXISTS FOR (n:ZzT) ON EACH [n.text] OPTIONS {indexConfig: {`fulltext.analyzer`: 'cjk'}} ``가 오류 없이 완료됐는데 조회하면 `There is no such fulltext schema index: zz_cjk`가 나옵니다.
- **원인** 같은 레이블·속성(ZzT.text)에 다른 이름(zz_std)의 전문 색인이 이미 있으면 IF NOT EXISTS가 별도 알림 없이 생성을 건너뜁니다(이름이 달라도 같은 대상이면 '이미 있음').
- **조치** `DROP INDEX zz_std IF EXISTS;`를 먼저 실행하고 다시 CREATE를 실행합니다. 확인: `SHOW INDEXES YIELD name, type, labelsOrTypes, properties;`
- **확인** *확인함* — DROP 후 다시 만들어 cjk 색인으로 `선임` 0.13 · `안전관리자 선임` 0.85가 조회됩니다.

### GL-03 · 기본 전문 색인이 「선임」으로 「선임하여야」를 찾지 못합니다 {#gl-03}

관련 장: [4장](cypher-basics.html)

- **증상** 기본 전문 색인에서 `CALL db.index.fulltext.queryNodes(…, '선임')`로 「…선임하여야 한다」 항을 찾지 못합니다(0건). `'선임*'`로만 찾을 수 있습니다.
- **원인** 기본 분석기(standard-no-stop-words)는 띄어쓰기 단위로 낱말을 나누므로 조사·어미가 붙은 한국어 낱말(선임하여야)은 「선임」과 다른 낱말로 처리됩니다.
- **조치** 한국어 본문 색인은 cjk 분석기로 만듭니다: `` CREATE FULLTEXT INDEX … OPTIONS {indexConfig: {`fulltext.analyzer`: 'cjk'}}; `` (분석기 목록: `CALL db.index.fulltext.listAvailableAnalyzers()`)
- **확인** *확인함* — cjk 색인으로 `선임` · `관리자` · `안전관리자 선임 신고` 모두 찾습니다(4장 녹화의 전문 색인 장면).

### GL-04 · 커밋을 요청했더니 실습 폴더 밖 메모리 파일을 수정하려 합니다 {#gl-04}

관련 장: [5장](schema.html)

- **증상** 「main에 커밋해 줘」라고 했더니 Claude Code가 `Wrote 1 memory`로 `~/.claude/projects/-Users-…-lab-law-graph/memory/commit-directly-on-main.md`를 만들고, 이어서 MEMORY.md 색인에 줄을 추가하는 Bash의 승인을 요청합니다(실습 폴더 밖 경로).
- **원인** Claude Code 자동 메모리(auto memory) 기능: 사용자 지시를 다음 세션용 메모로 남깁니다. 메모 파일 작성은 승인 없이 진행하고, 색인에 추가하는 Bash만 승인을 요청했습니다.
- **조치** 권한 요청에서 3(No) → 「메모리 파일은 건드리지 말고 넘어가자. 실습 폴더 밖은 고치지 마.」 (메모를 아예 끄려면 /memory 또는 설정에서 자동 메모리 끄기)
- **확인** *확인함 — 메모 파일 1개는 남음* — 색인 추가는 반영되지 않았고, 메모 파일 1개(796B)는 남았습니다. 실습 결과에는 영향이 없습니다.

## 인제스천

### GL-06 · 적재한 조문의 띄어쓰기가 PDF와 다릅니다 {#gl-06}

관련 장: [6장](ingest.html)

- **증상** 적재한 시행령 제21조 머리글이 「다만, 동일한시ㆍ도에 있는 둘 이상의…」로 붙어 나옵니다(PDF 원문은 「동일한 시ㆍ도에」). PDF에서 낱말 사이에 줄바꿈이 있어 띄어쓰기 여부를 알 수 없습니다.
- **원인** PyMuPDF로 읽은 글을 줄 단위로 이을 때 앞줄 끝의 여백과 다른 줄에 나온 낱말만으로 띄어쓰기를 추정했고, 근거가 없으면 붙였습니다(첫 판).
- **조치** Claude Code에 「시행령 제21조 머리글이 「동일한시ㆍ도에」로 붙었어. PDF 원문은 「동일한 시ㆍ도에」야. 줄바꿈 자리 띄어쓰기 규칙을 고쳐 줘 …」 → 어절 끝(조사·어미)·인용 표기 뒤·닫는 낫표 뒤·여는 따옴표 앞이면 띄우는 규칙을 추가합니다. `uv run parse_law.py && uv run ingest.py --prune`
- **확인** *확인함 — 규칙으로 판단하지 못한 자리 약 9%는 남음* — 위험물 3종 줄바꿈 자리 692곳 중 25곳(9개 법령 3,871곳 중 78곳)이 붙임→띄움으로 바뀌었고, 법 제15조·영 제21조·규칙 제53조의 공백을 뺀 글자 수가 PDF와 일치합니다(1,167·567·674). 규칙으로 판단하지 못한 자리(약 9%)는 여전히 붙여 둡니다.

### GL-07 · 같은 조 번호가 두 번 나와 덮어씁니다 {#gl-07}

관련 장: [6장](ingest.html)

- **증상** 폐기물관리법 제13조의2·제68조, 폐기물관리법 시행규칙 제10조가 PDF에 두 번 나옵니다(현행 조문 뒤에 같은 번호의 시행 예정 조문이 있으며, 끝에 `[시행일: 2027. 7. 8.]` 등). 조 번호만으로 MERGE하면 뒤의 조문이 앞의 조문을 덮어쓰거나 항·호가 섞입니다. 부칙의 제1조·제8조도 본칙 번호와 겹칩니다.
- **원인** 국가법령정보센터 PDF는 시행일이 다른 판본을 같은 문서에 함께 싣습니다.
- **조치** 이번 파서는 부칙을 조문 노드로 적재하지 않고, `[시행일: …]` 꼬리표가 붙은 판본은 pid에 `@YYYYMMDD`를 붙여 따로 적재합니다(isCurrent=false, effectiveFrom). 질의에서는 isCurrent=true만 조회합니다. 확인 질의: `MATCH (a:Article) WHERE NOT a.isCurrent RETURN a.pid, a.effectiveFrom`
- **확인** *확인함* — 그래프에 `폐기물관리법:제68조`(현행, 3,091자)와 `폐기물관리법:제68조@20270108`(3,104자), `제13조의2`(703자)/`@20270708`(768자), 시행규칙 `제10조`(3,079자)/`@20261210`(3,057자)가 따로 있습니다. 현행·비삭제 조 수: 위험물 46·29·82, 화학 76·32·74, 폐기물 99·68·150 (삭제 조까지 포함하면 46·29·82, 79·34·85, 110·72·158 — PDF의 「제N조(」·「제N조 삭제」 줄 집합과 그래프의 조 집합이 9개 법령 모두 일치합니다)

### GL-08 · 다시 적재했는데 삭제되어야 할 관계가 남아 있습니다 {#gl-08}

관련 장: [6장](ingest.html)

- **증상** 추출 규칙을 고쳐 다시 `uv run ingest.py`를 실행했는데, 수정 후에는 없어야 할 MENTIONS 관계 7개가 DB에 그대로 남습니다.
- **원인** MERGE는 기존 항목을 유지하고 없는 항목만 추가합니다. 다시 실행해도 중복은 생기지 않지만, 이번 추출에서 빠진 기존 노드·관계는 삭제하지 않습니다.
- **조치** Claude가 ingest.py에 --prune 옵션(이 스크립트의 레이블이 붙은 노드·관계 중 이번 추출에 없는 항목 삭제)을 추가했습니다: `uv run ingest.py --prune` (`data/`에 9개 법령이 모두 있을 때만). 처음부터 다시 적재하려면: `uv run ingest.py --reset`
- **확인** *확인함* — --prune을 한 번 실행한 뒤 7개만 삭제됐고, 옵션 없이 다시 적재해도 노드 6,272·관계 17,537이 그대로 유지됩니다.

### GL-09 · 가운뎃점을 「·」로 통일했더니 「도지사」 검색 결과가 1건뿐입니다 {#gl-09}

관련 장: [6장](ingest.html)

- **증상** 전문 색인에 가운뎃점을 「·」로 통일해 넣었더니 「도지사」로 찾을 때 조문이 1건만 검색됩니다.
- **원인** Lucene(전문 색인)이 「·」를 낱말을 잇는 글자로 보아 「시·도지사」·「위치·구조·설비」를 한 낱말로 묶습니다.
- **조치** 전문 색인용 텍스트(normText·searchText)는 가운뎃점을 공백으로 바꿔 넣고, 용어 키(normName·normKeys)만 「·」로 통일합니다(lawtext.py search_text / norm_key).
- **확인** *확인함* — 변경 후 「도지사」는 37건이 검색됩니다. 「위치·구조·설비」 1건 → 「위치 구조 설비」 12건으로 바뀝니다.

## 중의성 해소

### GL-10 · LLM 중의성 해소가 서로 다른 주체를 합치고 약칭은 묶지 못합니다 {#gl-10}

관련 장: [7장](disambiguation.html)

- **증상** WorkFlowy 자료의 LLM 중의성 해소 프롬프트(값 목록 → 같은 엔티티에 같은 번호)로 주체 이름 228가지를 haiku에 한 번 보냈더니 「관계인」=「관계자」, 「대리자」=「대리인」, 「자」=「사람」=「누구든지」를 같은 번호로 묶고, 약칭(탱크시험자/탱크안전성능시험자, 시ㆍ도/특별시ㆍ광역시ㆍ…)은 묶지 못합니다. 「소방본부장 또는 소방서장」 같은 묶음 이름은 나누지 않고 하나의 엔티티로 둡니다.
- **원인** LLM은 이름 목록만 받아 조문의 문맥이나 법에서 정한 약칭을 알지 못하고, 뜻이 비슷해 보이는 낱말을 합칩니다. 규칙·사전 방식은 근거가 분명하지만 228가지 중 200가지를 개별 항목으로 남깁니다.
- **조치** 두 방법을 결합하고 사람이 검토합니다: 묶음 이름은 「또는·및·,」로 나누어 개별 Actor에 연결, 소방본부장≠소방서장 검사, 관계인+수식어는 합치고 관계자는 분리, 자·사람·누구든지는 Actor에서 제외, 약칭은 Term 사전 우선. 잘못 묶인 이름은 ingest_semantic.py의 `STAND_ALONE` 목록에 넣고 `uv run ingest_semantic.py --reset`을 실행합니다.
- **확인** *확인함 — 남은 한계 있음* — Actor 228가지 → 134 → (대리인·탱크시험자의 업무에 종사하는 자 분리) 136. 소방본부장·소방서장은 별개 노드이며, 관계인의 9가지 표기 → 1 노드(별칭 8)로 바뀝니다. 질문 2번의 「위험물안전관리자」「관계인」이 별칭 키로 Term·Actor에 연결됩니다. 남은 한계: kind=기타 비주체 Actor 51개, 수식절을 떼고 합친 14가지

- **확인 못 함** Neo4j Desktop(PBL 특강 교재의 방식)이나 다른 Neo4j 컨테이너가 이미 실행 중이면 `docker run`이 포트를 잡지 못해 컨테이너가 시작되지 않습니다(이 기록에서는 겪지 않아 오류 문구가 없습니다). 포트 사용 주체는 macOS·Linux에서 `lsof -i :7687`, Windows에서 `netstat -ano | findstr 7687`, 컨테이너라면 `docker ps`로 확인합니다.

- **확인함** 이 교재의 설정(힙 512m~1G, 페이지 캐시 512M, 컨테이너 상한 `--memory 2g`)으로 모든 장을 마쳤습니다. 컨테이너 메모리는 시작 직후 926.4MiB / 2GiB, 의미층 적재와 질의까지 마친 뒤 1.49GiB / 2GiB였습니다. 그때 DB 폴더(`neo4j/data`)는 트랜잭션 로그를 포함해 약 530MB였습니다.

### Apple Silicon·Intel, Windows 경로 차이

- **확인함** Apple Silicon macOS에서 `neo4j:5.26`은 arm64 버전으로 내려받아 그대로 실행했습니다(`docker image inspect neo4j:5.26 --format '{{.Architecture}}'` → `arm64`). 마운트한 폴더의 소유자를 바꾼다는 경고(`Changing folder owner to neo4j`)는 무해했습니다.

## 알려진 제약

- **별표·서식 본문이 없습니다.** PDF에 이름만 있어 과태료 세부 금액(시행령 별표 9), 행정처분 기준, 신고서 서식 내용은 답할 수 없고 상한(예: 500만원 이하)만 제시됩니다.
- **줄바꿈 자리 띄어쓰기의 약 9%는 정하지 못했습니다.** 9개 법령의 줄바꿈 자리 3,871곳 가운데 규칙으로 정하지 못한 자리는 붙여 두었습니다. 위험물안전관리법 3종의 표본 3개 조만 PDF와 글자 단위로 대조했고, 전체를 확인하지는 않았습니다.
- **화학물질관리법·폐기물관리법은 대조하지 않았습니다.** 두 법의 벌칙 연결(`PENALIZES`)과 `Term`은 원문과 대조하지 않았고, 「변경」「용기」 같은 흔한 낱말이 괄호 정의로 잡혀 용어가 된 경우가 있습니다. 해결하지 못한 인용 7건도 검토하지 않았습니다.
- **법령마다 시행일이 다릅니다.** 위험물안전관리법은 2025-08-07, 시행령·시행규칙은 2026-07-01 기준입니다. 답변에는 `Law.effectiveOn`을 함께 보여 주세요.
- **의미층은 검수 전입니다.** 위험물안전관리법 3종만 넣었고 `Norm`은 모두 `reviewed=false`입니다. GL-14(「 밖의 관계기관」 Actor)는 기록을 같은 데이터로 남기려고 고치지 않았습니다. 주체가 아닌 말이 `Actor`로 남은 것(kind=기타 51개), 수식절을 떼고 넓게 합친 이름 14가지, 조문 텍스트와 달라 값을 비워 둔 `Norm` 속성(trigger 104건·deadline 6건, `uncheckedFields`에 표시)도 남아 있습니다. `DELEGATED_TO`·`NEXT`·`ON_BREACH_OF`·`SANCTIONED_BY` 관계는 아직 추출하지 않았습니다.
- **비용 수치는 환산치입니다.** `claude -p`의 `total_cost_usd`는 API 요금 환산치이며 구독 로그인이라 실제 청구액이 아닙니다. 9개 법령 전체를 추출할 때의 비용은 글자 수에 비례해 추산한 값입니다.
- **법령 해석은 원문으로 확인하세요.** 그래프와 모델의 답은 근거 조문을 찾아 주는 도구이며, 판단은 원문과 담당자의 몫입니다.

본문의 화면과 수치는 아래 환경에서 얻었습니다. 이 절의 항목은 학습자의 기본 설치 환경에서는 발생하지 않습니다.

- **기록일과 버전:** 2026-11-24, macOS(Apple Silicon), Docker Desktop 29.1.2, Neo4j 5.26.33 Community(`neo4j:5.26`), Claude Code 2.1.331(Fable 5.2, medium effort, Claude Ultra 플랜), uv 0.9.18, Python 3.12.12, PyMuPDF 2.1, Neo4j MCP 서버 2.1.2.

- **Claude Code 설정:** 프로젝트 `.claude/settings.local.json`에 `disableAllHooks: true`(이 맥의 명령 변환 훅을 끄려고)와 `effortLevel: medium`을 두었습니다. 권한 요청은 녹화 도구가 화면을 읽어 승인했고(위험한 명령과 실습 폴더 밖 경로에서는 멈춤), 삭제 명령(`ingest.py --prune`)과 실습 폴더 밖 메모리 색인 쓰기는 사람이 검토해 승인 여부를 결정했습니다.
- **git:** 녹화 전에 실습 폴더에 `.git`이 이미 있어 `git init`이 「빈 깃 저장소를 다시 초기화했습니다」라고 나왔습니다. 새로 시작하면 「초기화했습니다」가 나옵니다.
- **남겨 둔 것:** 5장에서 생긴 자동 메모리 파일 하나(GL-04)는 실습 폴더 밖에 그대로 두었습니다.

### GL-01 · tmux로 보낸 명령에서 세미콜론이 사라집니다 {#gl-01}

관련 장: [3장](neo4j-docker.html)

- **증상** tmux로 입력한 명령에서 세미콜론이 사라집니다: `curl -s localhost:7474; echo`가 `curl -s localhost:7474 echo`로 들어가고, cypher-shell 문장 끝의 `;`가 빠집니다.
- **원인** tmux send-keys는 단독 인자 `;`를 tmux 명령 구분자로 처리합니다(-l을 지정해도 그 글자 하나만 보내면 해당합니다).
- **조치** tools/type.sh에서 `;`는 `\;`로 보내도록 수정했습니다(이미 반영). 직접 보낼 때: `tmux send-keys -t gl -l '\;'`
- **확인** *확인함* — 고친 뒤 `echo a; echo b`와 cypher-shell `…;`이 그대로 입력되는 것을 확인했고, 3장 녹화의 해당 장면은 다시 촬영했습니다.

### GL-13 · claude가 auto mode로 실행되고 /mcp에 다른 서버가 함께 보입니다 {#gl-13}

관련 장: [5장](schema.html), [8장](mcp.html)

- **증상** claude를 실행할 때마다 `⏵⏵ auto mode on`으로 시작하고, /mcp에 easel(plugin)·computer-use가 함께 보입니다.
- **원인** 이 맥 사용자의 전역 설정(~/.claude/settings.json: autoMode·플러그인)이 프로젝트에도 적용됩니다. 학습자의 기본 설치 환경에는 없습니다.
- **조치** 녹화에서는 shift+tab 한 번으로 manual mode(묻고 실행)로 전환했습니다. 전역 설정은 수정하지 않았습니다(프로젝트 .claude/settings.local.json에 disableAllHooks·effortLevel medium·code-review-graph 플러그인 비활성화만 설정했습니다). 편집할 때 /mcp 화면의 easel·computer-use 줄은 가리거나 설명합니다.
- **확인** *확인함* — manual mode로 전환되고 권한 요청이 표시되는 것을 녹화로 확인했습니다.
