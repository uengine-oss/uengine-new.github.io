# 설치와 첫 로그인

> Docker가 있는 PC 한 대에 명령 한 줄로 Process GPT Lite를 설치하고, LLM 키를 넣고, 이메일로 받은 코드로 처음 로그인합니다. 로그인 뒤에 이어지는 첫 화면 안내(생년월일 → 인사 → 메일 연결)까지 마치면 2장부터 실습할 준비가 끝납니다.

## 무엇이 설치되나

Process GPT Lite는 **화면(웹 앱)** 과 그 뒤에서 일하는 **Process GPT 백엔드**로 이루어져 있습니다. 설치 스크립트는 이 모두를 Docker 컨테이너로 내려받아 빌드하고, 데이터베이스를 준비하고, 첫 관리자 계정까지 만들어 줍니다.

| 구성 | 하는 일 |
|---|---|
| 웹 앱과 서버 | 지금부터 보게 될 화면. 채팅·홈·설정·보관함·브라우저 에이전트 |
| 로그인·저장소 | 이메일 로그인, 대화와 파일 저장 (오픈소스 Supabase의 최소 구성) |
| 에이전트 | 대화를 받아 실제로 일하는 AI 에이전트(deepagents)와, 에이전트가 파일을 다루는 격리된 작업 공간(샌드박스) |
| 문서 | 한글·워드·엑셀 문서를 만드는 문서 서버와, 화면 안에서 고치는 편집기(이음오피스) |
| 메일함 | 로그인 코드를 받는 설치 전용 메일함(mailpit) |

모든 것이 내 PC 안에서 돕니다. 바깥으로 나가는 것은 LLM 호출(설정한 API 주소)과, 연결했을 때의 메일·외부 서비스뿐입니다.

## 준비물

| 항목 | 최소 | 권장 |
|---|---|---|
| Docker | Docker Desktop 4.x 또는 Docker Engine 24 이상 (Compose v2) | |
| Docker에 할당한 메모리 | 6GB (실행 중에는 약 1.5GB 사용) | 8GB 이상 (처음 빌드할 때) |
| CPU | 4코어 | 8코어 |
| 디스크 | 20GB (이미지 약 11GB와 빌드 캐시) | 30GB |
| LLM | OpenAI 호환 API의 주소·키·모델 이름 | |

macOS, Linux, Windows(WSL2)에서 설치할 수 있습니다. Windows는 WSL2 안에 Docker Engine을 설치해 쓰는 것을 권장합니다.

## 설치하기

터미널에서 한 줄을 실행합니다. 저장소를 `~/process-gpt-lite`에 받고 설치 스크립트를 실행합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/uengine-oss/process-gpt-lite/main/install/get.sh | bash
```

저장소를 직접 받아도 같습니다.

```bash
git clone https://github.com/uengine-oss/process-gpt-lite.git
cd process-gpt-lite/install
./install.sh
```

스크립트가 몇 가지를 묻습니다. 괄호 안이 기본값이고, 그냥 Enter를 누르면 기본값을 씁니다.

| 질문 | 예 | 설명 |
|---|---|---|
| LLM 주소(OpenAI 호환) | `https://api.openai.com/v1` | 사내 모델 서버나 다른 OpenAI 호환 주소도 됩니다 |
| LLM API 키 | (입력해도 화면에 보이지 않습니다) | 비워 두면 채팅이 답하지 않습니다 |
| 기본 모델 | `gpt-4.1` | 에이전트가 일할 때 쓰는 모델 |
| 빠른 모델(라우팅·분류) | 기본 모델과 같게 | 메시지 분류, 메일 분석처럼 짧은 판단에 쓰는 모델 |
| 첫 관리자 이메일 | `admin@pgpt-lite.local` | 설치가 끝나면 이 주소가 관리자 계정이 됩니다 |

처음에는 이미지를 빌드하느라 **20~40분** 걸립니다(이음오피스 편집기가 가장 오래 걸립니다). 끝나면 다음과 같은 요약이 나옵니다.

```text
  Process GPT Lite 가 준비됐습니다

    주소        http://localhost:18080
    관리자      admin@pgpt-lite.local
    로그인 코드  이메일을 입력하면 코드가 메일함으로 갑니다 → http://localhost:18025
```

!!! tip "묻지 않고 설치하기"
    여러 대에 똑같이 설치할 때는 값을 환경 변수로 주고 `--yes`를 붙입니다.

    ```bash
    LLM_API_KEY=… LLM_BASE_URL=… LLM_MODEL=… ADMIN_EMAIL=… ./install.sh --yes
    ```

### 프로필 — 무엇까지 띄울까

| 프로필 | 들어 있는 것 | 이럴 때 |
|---|---|---|
| `lite` (기본) | 채팅·에이전트·문서 생성과 편집·공유 폴더·패널 앱·보관함·브라우저 에이전트 | 1~4부(혼자, 문서, 반복 줄이기, 팀)를 따라 할 때 |
| `full` (실험) | lite + 프로세스 엔진 + 외부 도구 연결 허브(MCP 허브) | 5부(프로세스) — 프로세스를 시작하고 진행할 때 `./install.sh --profile full` |
| `mining` (선택) | 위에 더해 프로세스 마이닝 | 반복된 일에서 프로세스를 추천받을 때 `./install.sh --with-mining` |

!!! note "설치 번들에 빠진 것"
    현재 설치 번들에는 대화를 주제별로 나누는 **대화 맥락 라우터**와 판단 모델이 들어 있지 않습니다(GPU나 큰 메모리가 필요합니다). 쓰려면 따로 띄운 뒤 `.env`에 주소(`CONTEXT_ROUTER_URL`, `JUDGE_URL`)를 넣어 연결하세요. 연결하지 않아도 채팅은 되지만 [4장](contexts.html)의 “대화가 알아서 나뉘는” 기능은 꺼집니다. 도면·그림·소리·영상 편집기(ArtCraft, [8장](craft.html))와 Claude Code 작업실([23장](workroom.html))도 따로 설치합니다.

## 설정 파일 `.env`

설치 폴더(`install/`)의 `.env`가 모든 설정을 담습니다. 처음 실행할 때 만들어지고, 권한은 본인만 읽을 수 있는 `0600`입니다. 데이터베이스 비밀번호, 로그인 토큰 서명 키, **보관함 마스터 키** 같은 비밀 값은 스크립트가 무작위로 만들어 채우며 화면이나 로그에 찍지 않습니다. 업그레이드해도 그대로 유지됩니다.

자주 손대는 값은 다음과 같습니다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | OpenAI 주소, 빈 값 | 모든 AI 기능이 쓰는 LLM |
| `LLM_MODEL`, `LLM_FAST_MODEL` | `gpt-4.1`, `gpt-4.1-mini` | 일하는 모델과 빠른 판단용 모델 |
| `LLM_EMBEDDING_MODEL` | `text-embedding-3-small` | 문서 검색용 임베딩 |
| `TRANSCRIBE_API_KEY` | 빈 값 | 원격 회의 받아쓰기(OpenAI 음성 API 키). 비우면 화상 회의만 되고 자막·회의록 글은 없습니다 ([16장](meetings.html)) |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | 빈 값 | Google 로그인과 Gmail 연결 ([5장](mail.html)) |
| `SMTP_HOST` 외 `SMTP_*` | 빈 값 | 로그인 코드를 실제 메일로 보낼 때. 비우면 번들 메일함으로 갑니다 |
| `DEMO_LOGIN` | `0` | `1`이면 고정 코드 `000000`도 받습니다 (아래 경고 참고) |
| `PUBLIC_URL`, `LITE_BIND` | `http://localhost:18080`, `127.0.0.1` | 다른 PC에서 접속할 때 바꿉니다 |

`.env`를 고친 뒤에는 `./install.sh`를 다시 실행하면 바뀐 값으로 컨테이너가 다시 뜹니다. 데이터는 그대로입니다.

## 포트와 접속 주소

| 포트 | 무엇 |
|---|---|
| `18080` | 앱 전체 — 웹 화면, 서버 API, 문서 편집기, 로그인이 모두 이 주소 하나로 들어옵니다 |
| `18025` | 번들 메일함 — 로그인 코드 메일을 여기서 읽습니다 |

기본으로는 **이 PC에서만** 열립니다(`127.0.0.1`). 18080을 다른 프로그램이 쓰고 있으면 `./install.sh --port 28080`처럼 바꿉니다. 팀원이 다른 PC에서 접속하게 하려면 `.env`에서 `PUBLIC_URL=http://<이 PC의 IP>:18080`, `LITE_BIND=0.0.0.0`으로 바꾸고 SMTP를 설정한 뒤 `./install.sh`를 다시 실행합니다. 번들 메일함은 이 PC에서만 열리기 때문입니다. 인터넷에 열 때는 앞에 HTTPS 리버스 프록시를 둡니다.

## 첫 로그인

브라우저로 `http://localhost:18080`을 엽니다. 왼쪽 하늘 그림 위로 “노스윈드 견적 요청 메일에 작년 조건으로 회신 초안 써줘” 같은 예시 문장이 한 글자씩 써집니다. 이 앱에 무엇을 시킬 수 있는지 보여 주는 예입니다.

![로그인 화면 — Google로 계속하기, 또는 이메일 주소로 계속](img/install-login.webp)

<ol class="steps" markdown="1">
<li>이메일 주소를 적고 「계속」을 누릅니다. 설치할 때 적은 관리자 이메일로 먼저 로그인해 보세요.</li>
<li>번들 메일함 <code>http://localhost:18025</code>를 열면 6자리 코드가 담긴 메일이 와 있습니다. SMTP를 설정했다면 실제 메일함으로 갑니다.</li>
<li>코드 여섯 칸에 입력하면 바로 로그인됩니다. 붙여 넣기도 됩니다.</li>
</ol>

![코드 입력 — 이 사진은 데모 로그인을 켠 개발용 서버라 “(로컬 데모: 000000)”이 함께 보입니다](img/install-code.webp)

`.env`에 `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET`을 넣었다면 「Google로 계속하기」로도 로그인할 수 있습니다. 넣지 않았으면 이 버튼은 “이메일로 계속해 주세요”라고 안내합니다.

!!! warning "데모 로그인은 닫힌 PC에서만"
    `DEMO_LOGIN=1`로 두면 **아무 이메일**이나 코드 `000000`으로 로그인됩니다. 시연이나 혼자 써 보는 PC에서만 켜고, 다른 사람이 접속할 수 있는 서버에서는 반드시 `DEMO_LOGIN=0`(기본값)으로 두세요. 끄려면 `.env`의 값을 `0`으로 바꾸고 `./install.sh`를 다시 실행합니다. 소스에서 직접 띄운 개발용 서버는 반대로 데모 로그인이 **기본으로 켜져** 있으므로, `server/.env`에 `PRO_DEMO_LOGIN=0`을 넣어 끕니다. 이 튜토리얼의 사진은 데모 로그인을 켠 개발용 서버에서 연습용 계정으로 찍었습니다.

!!! note "표시 이름"
    Google로 로그인하면 Google 계정의 이름이, 이메일 코드로 로그인하면 주소의 `@` 앞부분이 화면과 팀원 목록에 쓰이는 이름이 됩니다. 현재 버전에는 이름을 바꾸는 화면이 없으므로, 사진 속 “장진영” 자리에 여러분의 이름이 보여도 그대로 따라 하면 됩니다.

## 처음 한 번 — 첫 화면 안내

처음 로그인하면 세 화면이 차례로 나옵니다. 한 번만 나오고, 다음부터는 바로 채팅 화면이 열립니다.

**① 생년월일.** 연령에 맞는 서비스를 위해 묻는 것이고 다른 사람에게 보이지 않습니다. 연도·월·일을 고르고 「계속」을 누릅니다.

![생년월일 묻기](img/install-age.webp)

**② 인사.** “process gpt, 저는 당신만의 업무 운영체제처럼 생각하시면 돼요.”라는 문장이 써진 뒤 저절로 채팅 화면으로 넘어갑니다.

![첫 인사 — 몇 초 뒤 저절로 넘어갑니다](img/install-intro.webp)

**③ 비서의 자기소개와 메일 연결.** 채팅에 비서가 세 문장으로 자기소개를 하고, 메일을 연결하자고 제안합니다. Google 로그인을 설정한 서버에서는 버튼이 「Google에 로그인」, 아니면 「메일 연결하기」로 보입니다.

![비서의 자기소개와 메일 연결 버튼](img/install-welcome.webp)

버튼을 누르면 연결 방법을 고르는 창이 뜹니다. **이 튜토리얼에서는 「데모 메일함」을 고릅니다.** 가상의 거래처 메일 다섯 통이 들어 있는 연습용 메일함이라, 실제 메일을 연결하지 않고도 다음 장들을 그대로 따라 할 수 있습니다. Gmail과 IMAP 연결은 [5장](mail.html)에서 자세히 다룹니다.

![연결되면 “데모 메일함 연결됨”으로 바뀌고, 비서가 메일을 살펴본 뒤 돌아오겠다고 합니다](img/install-connected.webp)

연결하고 1분쯤 지나면 비서가 메일을 읽고 채팅에 **오후 브리프**(아침이면 모닝 브리프)를 남기고, 홈에 할 일 카드 네 장을 올립니다.

## 멈추기·업그레이드·지우기

| 하고 싶은 것 | 명령 (`install/` 폴더에서) |
|---|---|
| 다시 시작 (몇 번 실행해도 안전) | `./install.sh` |
| 새 버전으로 업그레이드 | `./install.sh --upgrade` |
| 멈추기 (데이터는 남김) | `./install.sh --uninstall` |
| 모두 지우기 (데이터·이미지·`.env`까지) | `./install.sh --uninstall --purge` |
| 상태와 로그 | `docker compose ps`, `docker compose logs -f server deepagents` |

### 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| “포트 18080 를 다른 프로그램이 쓰고 있습니다” | `./install.sh --port 28080` |
| 로그인 코드가 안 옴 | `http://localhost:18025` 메일함, `docker compose logs auth` |
| 채팅이 답하지 않음 | `.env`의 `LLM_*` 값, `docker compose logs deepagents` |
| 에이전트가 파일 작업에서 멈춤 | Docker 소켓 권한 (Linux는 사용자가 `docker` 그룹에 있어야 합니다) |
| 문서가 편집기에서 빈 화면 | `docker compose logs office-host` |
| 빌드가 메모리 부족으로 실패 | Docker 메모리를 8GB 이상으로 늘리고, 다른 컨테이너를 잠시 멈춥니다 |

3. `.env`에서 `DEMO_LOGIN=1`로 바꾸고 `./install.sh` → 행사 뒤 `DEMO_LOGIN=0`으로 되돌리고 다시 `./install.sh`. 켜져 있는 동안은 누구든 아무 이메일로 로그인할 수 있다는 점을 기억하세요.
