# AI-DLC 대시보드 — 개발 팀의 진행과 사람 대기를 홈에서 봅니다

> AWS Labs의 AI-DLC로 일하는 저장소를 공유 폴더로 연결하면 폴더 구성원이 작업 현황·사람 대기·볼트·품질·감사 기록·질문을 홈 패널에서 확인합니다. 숫자는 저장소의 `aidlc/` 기록에서 바로 계산하고, AI-DLC가 움직이는 동안 패널을 20초마다 갱신합니다.

## 왜 필요한가

AI-DLC(AI-Driven Development Life Cycle)는 AI가 단계마다 질문을 남기고 결과물을 만들면, 사람이 답하고 승인해야 다음 단계로 넘어가는 개발 방식입니다. 진행 기록은 모두 저장소의 `aidlc/` 폴더에 남습니다. 현재 단계를 담은 상태 파일, 시간순으로 쌓인 감사 기록, 질문 파일, 검토 보고서입니다. AI-DLC 사용법은 AX School [AI-DLC 핸즈온](https://www.uengine.org/docs/aidlc-handson/)에서 처음부터 따라 해 볼 수 있습니다.

문제는 이 기록을 Claude Code 터미널과 마크다운 파일에서 찾아야 한다는 점입니다. 팀 리드, PO, 아키텍트, QA가 "지금 누가 무엇을 기다리나", "어느 단계에서 사람을 오래 기다렸나"를 알려면 파일을 열어 읽어야 합니다. Lite는 이 기록을 그대로 읽어 각자의 역할에 맞게 홈 패널로 보여 줍니다. 따로 입력할 필요가 없습니다.

| 패널 | 보여 주는 것 | 어디서 계산하나 |
|---|---|---|
| 작업 현황 | 지금 단계와 담당 역할, 단계 레일, 기다리는 승인, 승인·반려·열린 질문 수 | 상태 파일, 감사 기록 |
| 사람 대기 | 단계마다 AI가 일한 시간과 사람을 기다린 시간, 반려 횟수 | 감사 기록의 단계 시작 → 승인 대기 → 승인 |
| 볼트 보드 | 구현 단위(유닛)마다 의존 관계, 상태, 작업 시간, 체크포인트 검증 성공·실패 | 유닛 계획, 감사 기록 |
| 품질 | 센서가 울린 횟수와 실패, 체크포인트 검증, 단계별 마지막 검토 판정과 남은 Major 지적 | 검토 보고서, 감사 기록 |
| 감사 타임라인 | 승인, 수정 요청, 답변, 센서 실패, 검증을 최근 기록부터 | 감사 기록 |
| 질문함 | 답을 기다리는 질문과 선택지, 질문 파일 위치 | 질문 파일 |

## 준비

| 항목 | 내용 |
|---|---|

## 따라 하기 2 — 진행 중인 작업이 움직이는 것을 보기

<ol class="steps" markdown="1">
<li>오세린으로 로그인해 <b>할 일 웹앱</b> 폴더를 엽니다. 띠에서 <code>todo-web-app · poc</code>를 고르고 <b>홈에 대시보드 추가</b>를 누릅니다.</li>
<li>홈의 작업 현황에는 지금 단계가 <b>의도 정리</b>로, 열린 질문이 <b>4</b>로 표시됩니다. 질문함에는 AI-DLC가 남긴 질문 네 개가 선택지와 함께 보입니다.</li>
<li>Claude Code에서 질문 파일(<code>intent-capture-questions.md</code>)의 <code>[Answer]:</code>에 답을 적습니다. 커밋하지 않아도 20초 안에 질문함이 「답을 기다리는 질문이 없어요」로 바뀝니다.</li>
<li>Claude Code에서 AI-DLC에 "답을 모두 적었어요. 이어서 진행해 주세요."라고 말합니다. AI-DLC는 결과물을 쓰기 전에 답을 요약하고 맞는지 묻습니다. 이 질문이 질문 파일 끝에 추가되므로, 질문함에 <b>요약 확인</b>이 다시 하나 생깁니다.</li>
<li>Claude Code에서 <code>1</code>(Looks correct)로 답합니다. AI-DLC가 의도 문서를 쓰는 동안 감사 타임라인에 질문에 답한 기록과 확인 요청 등이 쌓입니다.</li>
<li>AI-DLC가 승인을 기다리면, 작업 현황의 대기 칸에 <b>의도 정리 · PO·기획 · 기다린 시간</b>이 나타납니다.</li>
</ol>

## 숫자를 읽는 법

- **AI 작업**은 단계를 시작한 때(또는 수정 요청 뒤 다시 시작한 때)부터 승인 대기에 들어간 때까지입니다. 다만 AI-DLC가 질문이나 요약 확인을 남기고 사람의 답을 기다린 동안은 뺍니다.
- **사람 대기**는 질문이나 요약 확인의 답을 기다린 시간에 승인 대기부터 승인 또는 반려까지 걸린 시간을 더한 값입니다. 빌드처럼 오래 걸리는 작업 뒤에 기록이 없는 시간도 AI 작업으로 계산합니다.
- 구현 단계는 유닛마다 따로 진행하므로 단계별 시간에서 제외하고 볼트 보드에서 확인합니다. 유닛의 사람 대기는 마지막으로 통과한 검증부터 승인까지입니다.
- 반려는 승인 대기에서 수정을 요청한 횟수입니다. 같은 단계의 검토 보고서가 여러 개이면 품질 패널에 회차(×2)로 표시됩니다.

## 알아 둘 점

- 대시보드는 읽기만 합니다. 승인과 반려는 지금처럼 AI-DLC(Claude Code)에서 합니다. 패널 안 스크립트는 `/api/aidlc/` 아래의 읽기 요청만 보낼 수 있습니다.
- 작업 사본을 바로 읽으므로 커밋하지 않은 변경 사항도 보입니다. 새 단계의 질문 파일은 최대 15초 늦게 집계될 수 있습니다.
- 기록 파일은 크기나 수정 시각이 바뀔 때만 다시 읽습니다. 실습 기록 전체(사건 1,577건)에서 첫 요약은 약 0.4초, 이후 요약은 5~30ms였습니다.
- 기록 형식은 AI-DLC 2.11.2를 따릅니다.

7부를 마칩니다. 다음 8부 「산업별 예시」에서는 전자 제품 시작품 요청 메일 한 통으로 회로 검토, 3D, 2D 도면, 제안서, 견적서를 준비합니다([29장](prototype-request.html)).
