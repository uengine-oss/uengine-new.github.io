# 자주 묻는 질문

> 설치, 키와 비용, 어떤 모델이 언제 불리는지, 개인정보와 데이터 위치, 인터넷이 없는 곳에서 쓰기, 휴대폰까지 — 튜토리얼을 따라 하며 자주 나오는 질문을 모았습니다.

## 설치

**Q. 꼭 Docker가 있어야 하나요?**
네. 설치 번들은 Docker Compose로 모든 구성을 띄웁니다. macOS·Linux·Windows(WSL2) 모두 됩니다. Windows는 WSL2 안에 Docker Engine을 설치해 쓰는 것을 권장합니다([1장](install.html)).

**Q. 처음 설치가 너무 오래 걸립니다.**
처음에는 이미지를 직접 빌드하느라 20~40분 걸립니다(이음오피스 편집기가 가장 오래 걸립니다). 두 번째부터는 캐시를 써서 빠릅니다. 미리 빌드한 이미지를 쓰려면 `.env`에 `LITE_IMAGE_PREFIX`와 `LITE_TAG`를 넣으면 빌드 대신 내려받습니다. 빌드가 메모리 부족으로 실패하면 Docker 메모리를 8GB 이상으로 늘리세요.

**Q. 어떤 프로필을 골라야 하나요?**
처음에는 기본 `lite`로 충분합니다. 1~4부(혼자, 문서, 반복 줄이기, 팀)가 모두 됩니다. 5부의 프로세스를 실행하려면 `./install.sh --profile full`, 반복된 일에서 프로세스를 추천받으려면 `--with-mining`을 더합니다.

**Q. 설치했는데 어떤 장의 기능이 안 보입니다.**
설치 번들에 기본으로 들어 있지 않은 것이 있습니다.

| 기능 | 이유 | 켜는 법 |
|---|---|---|
| 대화가 주제별로 나뉨 ([4장](contexts.html)) | 판단 모델이 GPU나 큰 메모리를 씀 | 대화 맥락 라우터를 따로 띄우고 `CONTEXT_ROUTER_URL` |
| @팀원 추천의 “관련된 사람” 순서 | 같은 판단 모델 | `JUDGE_URL` (없으면 자주 주고받은 순서만) |
| 도면·그림·소리·영상 편집기 ([8장](craft.html)) | 운영체제별 빌드가 필요 | 웹 빌드를 서버 데이터의 `craft/<앱>/`에 넣음. 없으면 그 파일은 링크로 열리고, 메일 초안은 평면도 없이 제안서·견적서만 |
| Claude Code·Codex 작업실 ([23장](workroom.html)) | 내 구독 로그인과 호스트의 CLI가 필요 | 별도 설치 |
| 회의 받아쓰기 ([16장](meetings.html)) | 음성 인식 키가 따로 필요 | `TRANSCRIBE_API_KEY` |

**Q. 다른 사람 PC에서도 접속하게 하려면요?**
`.env`에서 `PUBLIC_URL=http://<이 PC의 IP>:18080`, `LITE_BIND=0.0.0.0`으로 바꾸고 SMTP를 설정한 뒤 `./install.sh`를 다시 실행합니다. 인터넷에 열 때는 앞에 HTTPS 리버스 프록시를 두고, 데모 로그인은 반드시 끕니다(`DEMO_LOGIN=0`).

**Q. 로그인 코드 메일이 안 옵니다.**
SMTP를 설정하지 않았다면 코드는 실제 메일함이 아니라 설치에 들어 있는 메일함 `http://localhost:18025`로 갑니다. 그래도 없으면 `docker compose logs auth`를 봅니다.

## 키와 비용

**Q. 어떤 키가 필요한가요?**
OpenAI 호환 API의 **주소·키·모델 이름** 하나면 됩니다(`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`). OpenAI가 아니어도 같은 방식으로 부르는 사내 모델 서버나 다른 공급자도 됩니다. 원격 회의 받아쓰기를 쓰려면 음성 인식 키(`TRANSCRIBE_API_KEY`)가, Google 로그인·Gmail 연결을 쓰려면 Google에 등록한 로그인용 클라이언트 정보(`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`)가 더 필요합니다.

**Q. 사용료가 있나요?**
Process GPT Lite 자체는 MIT 라이선스 오픈소스라 사용료가 없습니다. 비용은 **LLM 호출 요금**입니다. 사내 모델 서버를 쓰면 그 비용만 듭니다.

**Q. 언제 어떤 모델이 불리나요?**

| 언제 | 어떤 모델 | 얼마나 |
|---|---|---|
| 채팅 메시지가 올 때 — 어떤 종류의 일인지 고르기 | 빠른 모델 (`LLM_FAST_MODEL`) | 메시지마다 짧게 한 번 (스킬 만들기·문서 요청처럼 갈 곳이 정해진 말은 건너뜀) |
| 실제로 일하기 — 답, 정리, 문서 작성, 파일 다루기 | 기본 모델 (`LLM_MODEL`) | 일의 크기에 따라 여러 번. **비용 대부분이 여기서 나옵니다** |
| 어느 대화의 후속인지 판단 ([4장](contexts.html)) | 작은 판단 모델 → 확신이 낮으면 AI 모델에 한 번 더 | 메시지마다. 판단 모델은 따로 띄운 서버라 API 요금이 없습니다 |
| 긴 답의 문서 카드 제목 | 빠른 모델 | 긴 답일 때 한 번 |
| 메일 확인 ([5장](mail.html)) | 기본 모델 | 5분마다 확인하지만 **새 메일이 있을 때만** 한 번. 새 메일이 없으면 부르지 않습니다 |
| 브라우저 에이전트 ([6장](browser.html)) | 기본 모델 (화면 사진을 읽으므로 이미지를 읽는 모델이어야 함) | 한 동작마다 한 번, 한 작업에 최대 40번 |
| 문서 생성 (한글 등) | 기본 모델 | 문서마다 |
| 편집 뒤 검수 ([7장](office.html)·[8장](craft.html)) | 기본 모델 (그림은 이미지를 읽음) | 열린 문서를 고쳤을 때 |
| 회의 받아쓰기 ([16장](meetings.html)) | 음성 인식 모델 (`TRANSCRIBE_API_KEY`) | 말하는 동안 계속 |
| 회의·대화방에서 “부탁”인지 알아채기 | 판단 모델 | 큰 모델은 부르지 않습니다 |
| 예약 미션 ([11장](missions.html)) | 기본 모델 | 정한 시각마다. 바뀐 게 없으면 채팅에 남기지 않을 뿐, 실행은 합니다 |

비용을 줄이려면 빠른 모델은 작고 싼 모델로 두고, 예약 미션의 주기를 너무 짧게 잡지 마세요. 브라우저 작업은 동작마다 화면 사진을 보내므로, 같은 정보를 커넥터(Google·Slack 등)로 가져올 수 있다면 그쪽이 쌉니다.

## 개인정보와 보안

**Q. 모델에는 무엇이 전달되나요?**
내가 보낸 메시지와 붙인 파일, 일에 필요한 대화 기록, 메일 확인 때는 **새 메일의 보낸 사람·제목·날짜·본문 앞부분**, 브라우저 작업 때는 **페이지 내용과 화면 사진**입니다. 이것들은 설정한 LLM 주소로만 갑니다. 회사 밖으로 내보내고 싶지 않다면 사내 모델 서버를 `LLM_BASE_URL`로 지정하세요.

**Q. 보관함에 넣은 비밀번호도 모델이 보나요?**
아니요. 보관함의 비밀번호·카드 번호·인증 코드는 **모델에게 가지 않습니다.** 브라우저 작업에서 비밀번호 칸을 만나면 모델은 “여기에 비밀번호를 넣어”라고만 말하고, 실제 값은 서버가 직접 입력합니다. 페이지 내용에서는 비밀 칸의 값이 지워지고, 모델이 보는 화면 사진에서는 비밀 칸이 검게 가려집니다([6장](browser.html)).

**Q. 보관함은 어떻게 암호화되나요?**
열쇠를 두 겹으로 씁니다. 항목은 사용자마다 따로 만든 **데이터 키(DEK)** 로 잠기고, 그 데이터 키는 다시 서버에만 있는 **마스터 키(KEK)** 로 잠가 저장됩니다. 마스터 키는 데이터베이스가 아니라 설치의 `.env`(`VAULT_KEK`)에 있으므로, 데이터베이스만 빼내서는 열 수 없습니다. 설정 › 보안 「검증」으로 내 보관함이 제대로 잠겨 있는지 값을 보지 않고 확인할 수 있습니다. 자세한 방식과 키 교체는 [6장](browser.html)과 [25장](admin.html)에 있습니다.

**Q. 팀원이 내 대화를 볼 수 있나요?**
아니요. 채팅과 프로젝트는 본인만 봅니다. 팀원은 내가 **공유한 파일**(받는 사람만 열 수 있게 허가가 붙고, 받은 사람은 자기 사본으로 편집), 내가 **@멘션으로 보낸 부탁**(대화 발췌가 함께 감), 함께 있는 **대화방과 공유 폴더**만 봅니다([14장](sharing.html)).

**Q. 데모 로그인은 위험하지 않나요?**
켜 두면 아무 이메일이나 `000000`으로 로그인되므로 위험합니다. 설치 번들은 기본으로 꺼져 있습니다(`DEMO_LOGIN=0`). 소스로 띄운 개발용 서버는 기본으로 켜져 있으니 `server/.env`에 `PRO_DEMO_LOGIN=0`을 넣으세요.

## 데이터

**Q. 데이터는 어디에 저장되나요?**
전부 설치한 PC 안입니다.

| 무엇 | 어디 |
|---|---|
| 대화, 카드, 팀, 프로세스, 보관함(암호문) | 데이터베이스 볼륨 |
| 만든 문서·첨부 파일 | 저장소 볼륨 |
| 공유 폴더, 서버 데이터 | 서버 데이터 볼륨 |
| 에이전트 작업 공간과 스킬 | 설치 폴더의 `data/deepagents/` |
| 설정과 비밀 값(마스터 키 포함) | 설치 폴더의 `.env` |

백업과 옮기기의 권장 절차는 [25장](admin.html)을 보세요. `.env`의 마스터 키를 잃으면 보관함 항목을 열 수 없으므로 함께 보관해야 합니다.

**Q. 처음 상태로 되돌리려면요?**
`./install.sh --uninstall --purge`는 데이터·볼륨·이미지·`.env`까지 모두 지웁니다. 되돌릴 수 없으니 먼저 백업하세요. 데이터를 남기고 멈추기만 하려면 `--purge` 없이 실행합니다.

## 인터넷이 없는 곳에서

**Q. 인터넷 없이 쓸 수 있나요?**
**사내 LLM 서버가 있으면 대부분 됩니다.** 모든 구성이 PC 안에서 돌고, 로그인 코드도 설치에 들어 있는 메일함으로 받을 수 있습니다. 다음은 인터넷이 필요합니다.

| 기능 | 인터넷 없이 |
|---|---|
| 채팅·문서·패널·공유·프로세스 | 사내 LLM 서버로 됨 |
| Google 로그인, Gmail·캘린더·YouTube 연결 | 안 됨 (이메일 코드 로그인과 IMAP 사내 메일은 됨) |
| 하늘 배경의 날씨, 메일 보낸 곳 로고 | 날씨 없이 기본 하늘(서울 기준), 로고 대신 글자 |
| 브라우저 에이전트 | 사내망 사이트만 |
| 원격 회의 | 같은 망 안에서는 됨. 받아쓰기는 음성 인식 서버가 필요 |

## 휴대폰

**Q. 휴대폰에서도 쓸 수 있나요?**
네. 같은 주소를 휴대폰 브라우저로 열면 휴대폰 배치(위에 홈·채팅·프로젝트·폴더 탭, 홈 아래 입력창)로 바뀝니다([2장](tour.html)). Android에서는 서버 주소만 넣으면 되는 앱도 있습니다([영상](https://youtu.be/TYg7S1WJ0YQ)). 휴대폰에서 접속하려면 설치 PC가 그 휴대폰에서 보이는 주소로 열려 있어야 합니다(위 “다른 사람 PC에서도 접속” 참고).

**Q. 휴대폰에서 원격 회의도 되나요?**
브라우저가 카메라·마이크를 허락하면 됩니다. 단, 브라우저는 HTTPS 주소(또는 `localhost`)에서만 카메라·마이크를 허락하므로, 휴대폰으로 회의하려면 HTTPS 리버스 프록시가 필요합니다.

## 그 밖에

**Q. 대화가 엉뚱한 주제에 붙었어요.**
판단 모델도 틀릴 수 있습니다. 대화 목록에서 원하는 대화에 들어가 다시 말하면, 판단 없이 그 대화로 곧장 갑니다([4장](contexts.html)).

**Q. 비서가 일하는 중에 멈추고 싶어요.**
답을 쓰는 동안 입력창 오른쪽 위에 보이는 「멈추기」를 누릅니다. 서버에서 하던 일까지 멈추고 “(답을 멈췄어요.)”가 남습니다. 브라우저 작업은 작업 카드의 ×나 「작업 취소」로 멈춥니다. 답을 기다리는 중에 같은 대화로 또 보내도 앞 일은 끊기지 않습니다. 새 메시지는 「대기」로 표시됐다가 앞 답이 끝나면 이어서 답합니다([3장](first-chat.html)).

**Q. 같은 일을 매번 설명하기 번거롭습니다.**
잘된 방법을 스킬로 저장하고([10장](skills.html)), 정해진 시각에 돌리고([11장](missions.html)), 여러 사람이 넘겨받는 일이면 프로세스로 만드세요([17장](process-create.html)). 반복된 일을 비서가 먼저 찾아 프로세스로 추천하기도 합니다([19장](mining.html)).

**Q. 프로세스로 만든 뒤에도 더 빨라질 수 있나요?**
네. 실행 기록이 쌓이면 어느 단계에서 기다리는 시간이 긴지(병목), 일하는 시간과 기다리는 시간의 비율(흐름 효율), 전체 기간을 좌우하는 단계의 사슬(크리티컬 패스)을 볼 수 있고, 개선을 적용한 뒤 전후를 비교합니다([20장](bottleneck.html)~[22장](critical-path.html)).

여기까지가 Process GPT Lite 튜토리얼입니다. 처음부터 다시 훑어보려면 [튜토리얼 첫 페이지](index.html)의 학습 순서로 돌아가세요.
