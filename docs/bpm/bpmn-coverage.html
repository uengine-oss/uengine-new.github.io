BPMN 지원 범위

uEngine6 bmt/sds-process-test 브랜치에서 BPMN 요소를 각각 실제로 실행해 본 결과입니다. 그대로 되는 것(✅), 우회하면 되는 것(◐), 안 되는 것(✗)을 요소 분류별로 모으고, 우회 방법과 해당 장을 적었습니다.

무엇을 · 왜#

모델러 팔레트에 있는 요소가 모두 엔진에서 실행되지는 않습니다. 이 페이지는 Camunda 문서의 「BPMN coverage」처럼, 이 브랜치에서 각 요소를 실행할 수 있는지 정리합니다.

  • 기준. uEngine6 bmt/sds-process-test 브랜치(시연 워크트리 demo/bpm6-tutorial, 커밋 0e163f07)와 그 프런트를 로컬 스택에서 실행해 확인했습니다. 다른 브랜치(main 등)에서는 결과가 다를 수 있습니다.
  • 방법. 정의를 화면 또는 BPMN XML로 만들어 배포하고, REST API·업무 목록·Kafka로 실행한 뒤, 작업 목록 표(bpm_worklist)·프로세스 변수·관리자 화면으로 결과를 확인했습니다. 「확인하지 못함」은 실행해 보지 않았다는 뜻입니다.
  • 판정. ✅ 그대로 됨 · ◐ 우회하면 됨(XML로 쓰기, API로 부르기 등) · ✗ 안 됨(엔진이나 화면을 고쳐야 함).

엔진은 BPMN 요소를 태그 이름으로 클래스에 대응시킵니다. 사람 작업은 org.uengine.kernel.HumanActivity, 스크립트 작업은 org.uengine.kernel.ScriptActivity, 그 밖의 요소는 org.uengine.kernel.bpmn.<태그 이름>(예: ServiceTask, ExclusiveGateway)입니다. 요소의 <uengine:properties> JSON 맨 위에 _type이 있으면 그 클래스로 바뀝니다(예: 서비스 작업을 org.uengine.kernel.bpmn.SQLTask로). 아래 표의 _type 칸은 이 값입니다. 자세한 규칙은 엔진 확장하기에 있습니다.

알려진 제약#

이 표는 한 브랜치의 결과입니다

✗ 로 적은 요소(임베디드 서브프로세스, 타이머, 신호·에스컬레이션·조건·terminate, 메일)는 이 튜토리얼의 따라 하기에 넣지 않았습니다. 엔진을 수정한 빌드에서는 결과가 달라지므로, 업그레이드할 때 이 페이지의 시험(research/verify-scripts/B-*.mjs와 같은 방식)을 다시 실행해 보세요.

  • 모델러 팔레트·렌치 메뉴에는 위의 ✗ 요소도 모두 나옵니다. 그릴 수 있다고 실행되는 것은 아닙니다.
  • 화면 패널이 일부 설정을 저장하지 못하는 요소(서비스·SQL·보내기·콜 액티비티·이벤트 키)는 XML 보기(</>)에서 직접 고칩니다. 고친 뒤 루트 _type이 남아 있는지 확인하세요.
  • 시작자를 정적 필드에서 읽기 때문에, 동시에 여러 사용자가 시작하면 첫 작업 담당자가 바뀔 수 있습니다. API로 시작할 때는 roleMappings로 시작 레인 사람을 적어 주세요.

확인 문제#

결재가 사흘 안 끝나면 독촉 작업을 만들고 싶습니다. 타이머 경계 이벤트를 쓰면 되나요?

이 브랜치에서는 안 됩니다. 타이머는 발화하지만 발화로 생긴 작업을 완료할 수 없어 인스턴스가 멈춥니다. 외부 스케줄러가 기한을 넘긴 작업을 찾아 이벤트(Kafka)를 보내고, 그 이벤트를 메시지 경계·이벤트 동기화로 받는 식으로 우회합니다.

「견적 입력 → 검토」 두 단계를 공급사마다 반복하려면 어떻게 그리나요?

다중 생성 서브프로세스의 몸통은 사람 작업 하나여야 합니다. 「견적 입력」만 다중 생성하고, 「검토」는 서브프로세스 뒤에 한 번 둡니다. 두 단계를 꼭 묶어야 하면 두 단계짜리 프로세스를 따로 만들어 콜 액티비티로 부르는 방법을 검토하세요(콜 액티비티의 다중 생성은 확인하지 못했습니다).

서비스 작업 패널에서 URL을 고쳐 저장했더니 배포 실패 메시지가 나옵니다. 왜인가요?

패널이 저장하면서 서비스 작업 JSON 맨 위의 _type을 지우고, 헤더에는 _type을 남깁니다. 엔진은 JSON 어딘가에 _type이 있으면 맨 위에도 있어야 읽을 수 있습니다. XML 보기에서 "_type":"org.uengine.kernel.bpmn.ServiceTask"를 다시 넣고 저장하세요.
