대화로 프로세스 만들기

한빛오피스의 장진영 팀장이 「영업 제안서 작성」 업무를 채팅으로 설명하면, 딥 에이전트가 단계 · 담당 · 흐름을 정리한 초안을 보여 주고 확인을 받은 뒤 BPMN 흐름도와 입력 폼을 작업 폴더에 만듭니다. 「저장」을 누르면 프로세스 정의로 저장됩니다.

왜 프로세스로 만드나#

한빛오피스 영업팀은 고객이 제안서를 요청하면 늘 같은 순서로 일합니다. 고객의 요청 내용을 받아 적고, 영업 담당자가 이를 바탕으로 제안서를 작성해 보냅니다. 지금은 메일과 메신저로 주고받기 때문에 요청의 처리 상황을 물어봐야 알 수 있습니다. 담당자가 바뀌면 받아 적은 내용이 사라지기도 합니다.

이 순서를 프로세스로 만들어 두면 이렇게 바뀝니다.

그때그때 프로세스로
다음에 누가 무엇을 할지 사람이 기억 단계와 담당이 정의에 적혀 있음
받아 적은 내용이 메일 · 메신저에 흩어짐 단계마다 정해진 입력 폼에 남음
진행 상황을 물어봐야 앎 한 건 한 건(인스턴스)의 진행이 화면에 보임

Process GPT의 프로세스는 BPMN으로 저장됩니다. BPMN은 업무 흐름을 단계 · 갈림길 · 담당 줄(레인)로 그리는 국제 표준 표기입니다. 직접 그릴 줄 몰라도 됩니다. 말로 설명하면 Process GPT가 그립니다.

따라 하기 1 — 설명 보내기#

홈(사이드바 맨 위 연필 아이콘)의 채팅 상자에서 에이전트가 「딥 에이전트 (LangGraph)」인지 확인합니다. 기본값으로 선택되어 있으므로 바꾸지 않습니다.

채팅 상자에 만들고 싶은 프로세스를 설명합니다. 누가 무엇을 하는지를 단계마다 설명하고, 폼이 필요하다는 점도 함께 알립니다. 이름을 「」로 적어 두면 그 이름으로 만듭니다.

「영업 제안서 작성」 프로세스를 만들어 줘. 고객이 요청사항을 입력하면 영업 담당자가 제안서를 작성해서 고객에게 전달하는 2단계 프로세스야. 단계마다 입력 폼도 만들어 줘.

따라 하기 2 — 초안 승인하기#

설명을 보내면 새 대화방이 열립니다. 실습에서는 약 10초 뒤 「이대로 진행할까요? 추가하거나 바꿀 단계가 있으면 알려주세요.」 창이 떴습니다. 단계와 각 단계의 담당 역할이 적혀 있습니다.

확인할 것: 단계 2개와 각 단계의 담당(고객, 영업 담당자). 문장은 실행할 때마다 조금씩 다릅니다.

창의 단추 하는 일
승인 이 초안대로 만듭니다
반려 + 의견 아래 칸에 고칠 점을 적어 보내면 초안을 고쳐 다시 묻습니다. 예: 고객 대신 영업 담당자가 요청을 받아 적게 해 줘
건너뛰기 답하지 않고 넘어갑니다

「승인」을 누른 뒤 「응답 제출」을 누릅니다. 「승인」만 누르면 보내지지 않습니다.

따라 하기 3 — 추가할 항목 고르기#

승인하면 약 5초 뒤 「이 프로세스에 추가할 항목을 골라주세요 (안 고르면 건너뜁니다)」 창이 뜹니다. 딥 에이전트가 이 프로세스에 추가하면 좋을 에이전트 · 스킬 · DMN(결정표) 후보를 제안한 것입니다. 실습에서는 에이전트 후보 「고객 입력 검증 담당」과 「영업 제안서 작성 담당」이 나왔습니다.

이 장에서는 사람이 하는 프로세스만 만듭니다. 「건너뛰기」를 누릅니다. 아무것도 고르지 않으면 에이전트 · 스킬은 만들지 않고, 흐름도와 폼만 만듭니다. 에이전트를 붙이는 방법은 9장과 13장에서 다룹니다.

따라 하기 4 — 생성 확인하고 저장하기#

실습에서는 보낸 지 약 50초 뒤 「프로세스를 생성했어요. 확인 후 저장 버튼을 눌러주세요.」라는 메시지가 나타났습니다. 오른쪽 패널의 진행 상황 다섯 단계가 모두 「completed」로 바뀌고, 작업 폴더에 파일 세 개가 생겼습니다.

작업 폴더의 파일 내용
영업 제안서 작성.bpmn 흐름도 — 아래 「미리보기」에 그려집니다
form/input_request.form 첫 단계(고객 요청)의 입력 폼
form/write_proposal.form 둘째 단계(제안서 작성)의 입력 폼

딥 에이전트는 작업 폴더에 먼저 파일을 만들고, 저장 여부는 사람이 결정합니다. 흐름도와 폼을 훑어본 뒤 작업 폴더 오른쪽 위의 「저장」을 누릅니다. 「✅ 저장이 완료되었습니다.」와 함께 「BPMN 프로세스 생성 결과」 카드(「저장됨」, 프로세스 이름과 ID)가 나옵니다.

홈으로 돌아가면 프로세스 정의 체계도의 「미분류」 아래에 「영업 제안서 작성」이 New 표시와 함께 생겼습니다.

이름을 누르면 정의가 열립니다. 고객 레인에 「영업 제안 요청사항 입력」, 영업 담당자 레인에 「제안서 작성 및 전달」이 있고, 시작에서 끝까지 화살표로 이어져 있습니다. 정의 화면은 다음 장에서 자세히 봅니다.

이 장에서 만든 프로세스#

단계 담당(레인) 입력 폼 체크포인트
영업 제안 요청사항 입력 고객 고객명 · 연락처 · 제안 제목 · 요청 상세 내용 · 첨부 파일 요청 접수 완료
제안서 작성 및 전달 영업 담당자 제안서 본문 · 제안서 제목 · 제안서 파일 · 고객 전달 메시지 작성 완료 · 고객 전달

체크포인트는 단계를 끝내기 전에 확인할 항목입니다. 실행할 때 모두 체크해야 「제출 완료」가 됩니다(6장). 생성할 때마다 폼 칸과 체크포인트는 달라집니다.

좋은 설명의 조건

  • “영업 담당자가 제안서를 작성해서”처럼 단계마다 누가(역할) 무엇을(산출물) 만드는지 말하세요.
  • “고객이 요청사항을 입력하면 … 전달하는”처럼 시작과 끝을 말하세요.
  • 폼이 필요하면 말하세요. 이름은 「」로 적으면 그대로 씁니다.
  • 갈림길(승인/반려)이 있으면 말하세요. 이 장에서는 일부러 뺐습니다.

기본 에이전트로도 만들 수 있습니다

「기본 에이전트 (LangChain ReAct)」로 같은 설명을 보내도 프로세스가 만들어집니다. 이때는 초안 창이 선택지 목록 형태로 나타나고, 만든 정의가 바로 저장됩니다. 7장에서 기본 에이전트로 만들어 봅니다.

다음 장으로#

다음 장에서는 방금 만든 정의를 열어 흐름도의 단계 · 레인과 각 단계의 폼을 살펴보고, 고친 내용을 버전으로 남깁니다(4장).

확인 문제

  1. 초안 창에서 「승인」만 누르고 기다리면 어떻게 되나요?
  2. 추가할 항목 창에서 아무것도 고르지 않고 「건너뛰기」를 누르면 무엇이 만들어지나요?
  3. 「프로세스를 생성했어요」가 나온 뒤, 정의 체계도에 프로세스가 생기게 하려면 무엇을 누르나요?
답
  1. 아무 일도 일어나지 않습니다. 「승인」을 누르면 선택만 됩니다. 「응답 제출」을 눌러야 딥 에이전트에게 전달됩니다.
  2. 에이전트 · 스킬 · DMN은 만들지 않고, 흐름도(.bpmn)와 각 단계의 입력 폼만 작업 폴더에 만듭니다.
  3. 작업 폴더 오른쪽 위의 「저장」입니다. 딥 에이전트는 작업 폴더에 먼저 만들고, 저장해야 프로세스 정의가 됩니다.
