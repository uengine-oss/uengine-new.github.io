Process GPT Lite 튜토리얼

AI 비서에게 말을 거는 첫 대화부터 시작해, 문서와 도구를 대화로 다루고, 반복되는 일을 스킬과 예약으로 줄이고, 팀원과 나누고, 마지막에는 즉흥적으로 하던 일이 회사의 정식 프로세스가 되기까지를 한 단계씩 따라 하는 실습서입니다.

이 튜토리얼에서 하는 일#

Process GPT Lite는 대화 하나로 일하는 AI 업무 비서입니다. 질문에 답하는 데서 그치지 않고 문서를 만들고 고치며, 브라우저를 대신 조작하고, 메일을 읽고 할 일을 제안하고, 팀원에게 일을 넘기고, 회의에 들어와 자료를 띄웁니다. 실행 엔진·에이전트·저장소는 오픈소스 Process GPT 백엔드를 그대로 쓰고, Lite는 그 위에 가벼운 화면을 얹은 것입니다.

이 튜토리얼은 기능을 하나씩 나열하지 않습니다. 한 회사의 일이 어떻게 진화하는지를 따라갑니다.

등장인물 역할
장진영 공간디자인 회사의 제안팀장. 이 튜토리얼에서 여러분이 맡는 사람입니다
김민지 디자이너. 평면도와 제안서 그림을 맡습니다
박서연 재무 담당. 견적과 비용을 검토합니다
사토 유키 도쿄 협력 스튜디오의 조명 디자이너. 일본어로 쓰고 말합니다(15~16장)
달빛커피 고객. 2호점 매장 설계 제안과 견적을 메일로 요청합니다

“달빛커피 2호점 제안서와 견적서를 보내 주세요”라는 메일 한 통으로 이야기가 시작됩니다.

  1. 혼자, AI 비서와 — 장진영 팀장은 처음에 비서에게 묻고, 찾게 하고, 메일을 정리하게 합니다. 대화는 주제별로 알아서 나뉩니다.
  2. 문서와 도구까지 — 비서가 평면도(CAD), 제안서(한글), 견적서(엑셀)를 만들고, 열려 있는 편집기 안에서 바로 고칩니다. 고친 뒤에는 의도대로 됐는지 스스로 검수합니다.
  3. 반복을 줄이기 — 비슷한 요청이 매주 오자, 잘된 방법을 스킬로 저장하고, 정해진 시각에 돌아가는 예약 미션과 팀이 함께 쓰는 패널 앱을 만듭니다.
  4. 팀으로 — 산출물을 김민지·박서연에게 공유하고, @멘션으로 넘기고, 메신저와 원격 회의로 함께 다듬습니다. 일본어로 일하는 사토 유키와는 메시지가 번역되고 회의가 통역됩니다. 회의 내용은 대화방에 저절로 남습니다.
  5. 프로세스로 — 같은 흐름이 쌓이자 프로세스 마이닝이 “메일 접수 → 도면·제안서·견적 → 재무 검토 → 회신”이라는 패턴을 찾아 관리자에게 추천합니다. 정식 등록된 뒤에는 새 요청 메일이 오면 알아서 프로세스가 시작되고, 단계마다 담당자와 에이전트가 정해집니다.
  6. 프로세스 개선 — 정식 프로세스가 몇 달 돌고 나면 기록이 쌓입니다. 어느 단계에서 시간이 새는지(병목), 일이 실제로 일하는 시간과 기다리는 시간 중 어디에 쓰이는지(가치 흐름), 전체 기간을 결정하는 단계가 무엇인지(제약과 크리티컬 패스)를 찾고, 개선안을 미리 계산해 본 뒤 프로세스를 고쳐 전후를 비교합니다.
  7. 확장과 운영 — Claude Code·Codex가 일하는 작업실, 시스템 구조, 운영과 보안을 살펴봅니다.

튜토리얼을 마치면, 새 고객 요청 하나를 받아 메일 → 산출물 → 팀 검토 → 회의 → 정식 프로세스까지 끝까지 이끌고, 쌓인 기록으로 그 프로세스를 더 빠르게 고칠 수 있게 됩니다.

학습 순서#

0 · 시작하기설치, 첫 로그인, 화면 둘러보기 1 · 나와 AI 비서첫 대화, 대화 맥락, 메일 비서, 브라우저 에이전트와 보관함 2 · 문서와 도구이음오피스, ArtCraft, 메일 한 통에서 평면도·제안서·견적서까지 3 · 반복 줄이기스킬, 외부 연동과 예약 미션, 패널 앱 4 · 팀으로 일하기공유 폴더, 산출물 공유와 @멘션, 메신저와 번역, 원격 회의와 통역 5 · 프로세스로 일하기대화로 프로세스 만들기, 실행, 프로세스 마이닝 6 · 프로세스 개선병목 찾기, 가치 흐름과 제약 이론, 크리티컬 패스와 개선 실행 7 · 확장과 운영에이전트 작업실, 구조, 운영과 보안, 에이전트 가드레일 8 · 종합 과제새 고객 요청을 처음부터 끝까지

각 장은 개념 → 따라 하기 → 확인 문제 순서로 되어 있습니다. 앞 장에서 만든 것을 다음 장에서 이어 쓰므로 순서대로 따라 하는 것이 좋습니다. 확인 문제의 답은 접혀 있으니, 먼저 스스로 해 본 뒤 펼쳐 보세요.

누구를 위한 튜토리얼인가#

  • 메일과 메신저로 일해 본 사람이면 1~4부를 따라 할 수 있습니다. 프로그래밍은 필요 없습니다.
  • 5부(프로세스)는 업무 흐름을 그려 본 경험이 있으면 좋지만, BPMN을 몰라도 됩니다. 프로세스도 대화로 만듭니다.
  • 6부(프로세스 개선)는 숫자를 읽을 줄 알면 됩니다. 가치 흐름, 제약 이론, 크리티컬 패스는 장 안에서 처음부터 설명합니다.
  • 7부(확장과 운영)는 사내에 설치·운영하는 담당자를 위한 내용입니다. Docker와 터미널을 조금 다룰 줄 알면 됩니다.

준비물#

항목 내용

디스크 20GB 이상 여유 (컨테이너 이미지 포함)
LLM 키 OpenAI 호환 API 키 하나. 받아쓰기(원격 회의)를 쓰려면 받아쓰기용 키도 필요합니다
코딩 에이전트 (선택) Claude Code 또는 Codex CLI — 7부의 에이전트 작업실에서 씁니다
브라우저 Chrome 또는 Edge 최신판. 원격 회의에는 카메라·마이크가 필요합니다

표기 약속#

  • 달빛커피 2호점 견적서 만들어 줘처럼 고정폭 글자는 입력하는 문장, 화면의 버튼 이름은 「이어서 작업」처럼 낫표로 씁니다.
  • 화면 사진은 튜토리얼용 계정으로 실제로 실행해 찍었습니다. 사람 이름과 회사, 메일은 모두 예제입니다.
  • 비서와 에이전트가 쓰는 문장은 실행할 때마다 조금씩 다릅니다. 사진과 문구가 똑같지 않아도, 장마다 적은 확인할 것(만들어진 파일, 카드, 상태)이 같으면 제대로 된 것입니다.
