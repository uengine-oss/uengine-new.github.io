자주 묻는 질문

설치 · 프로젝트 · 프로포절 · Claude Code · 데이터 소스에서 자주 막히는 곳과 풀이입니다.

설치와 실행#

Neo4j를 따로 깔아야 하나요? 아닙니다. Lite는 설계를 Ontological DB에 둡니다. 앱이 Docker로 그래프 DB와 분석 서비스 컨테이너 일곱 개를 직접 올립니다(1장).

OpenAI API 키가 꼭 필요한가요? 이 튜토리얼은 키 없이 됩니다. 프로포절의 분석 · 계획 · 구현은 내 컴퓨터의 Claude Code가 하고, 요구사항 문서도 프로포절에 붙여 넣으면 키 없이 나뉩니다(12장). 레거시 코드 분석(13장)도 분석기의 AI 호출을 앱이 Claude Code로 넘깁니다. 요구사항 탭의 문서 업로드, 설계 탭의 채팅 수정 같은 앱 안 AI 보조에만 OpenAI 키가 필요합니다.

Claude Code는 왜 필요한가요? Robo Architect의 엔진이 Claude Code의 스킬이기 때문입니다. 터미널에서 claude 를 한 번 실행해 로그인해 두면, 앱이 그 로그인으로 스킬을 부릅니다(10장).

프로젝트#

프로젝트를 여러 개 만들 수 있나요? 네. 홈의 프로젝트 바꾸기에서 새 이름으로 만들기를 누르면 그래프가 하나 더 생깁니다. 프로젝트마다 그래프가 따로라서 설계가 섞이지 않습니다. 10장의 skill_lab 이 그 예입니다.

프로젝트 이름이 거절됩니다. 영문 소문자로 시작하고 소문자 · 숫자 · 밑줄(_)만, 2~40자여야 합니다. hanbit-delivery(하이픈)나 Hanbit(대문자)은 안 됩니다.

프로포절#

Plan 생성이 처음부터 다시 시작됐습니다. 생성 중에 그 탭을 새로고침하거나 그 탭에서 다른 화면으로 옮기면 처음부터 다시 합니다. 기다리는 동안 다른 일은 홈에서 새 탭을 열어 하세요.

「작업 분해 결과 파싱 실패」가 나옵니다. 작업 목록 생성에서 Claude의 응답을 작업 목록으로 읽지 못했다는 뜻입니다. 이 튜토리얼에서도 두 번 이렇게 끝났고 세 번째에 15개 작업이 나왔습니다. 작업 목록 생성을 다시 누르세요.

헌장을 고쳤더니 계획이 「오래됨」이 됐습니다. 그 헌장에 기대던 계획이라서입니다. 해당 프로포절의 Plan을 다시 생성해 확정하세요(4장).

헌장 인터뷰의 질문을 바꾸고 싶습니다. 질문 순서는 앱이 정합니다. 스킬 robo-project-constitution 은 질문의 추천 · 근거와 헌장 문서를 맡습니다(10장).

Claude Code#

코드 탭의 터미널이 글자 색 테마부터 묻습니다. 이 컴퓨터에서 Claude Code를 터미널로 처음 켜면 한 번 묻습니다. 위아래 화살표로 고르고 Enter를 누르세요.

구현을 시작하니 「Is this a project you created or one you trust?」가 나옵니다. Claude Code가 샌드박스 폴더를 처음 열 때 묻는 폴더 신뢰 확인입니다. 기본 선택이 「No, exit」이니 아래 화살표로 Yes, I trust this folder를 고른 뒤 Enter를 누르세요. 그다음 권한 우회 모드 동의가 나오면 Yes, I accept를 고릅니다. 구현이 시작되지 않았으면 셀에 /robo-implement PRO-001 을 직접 입력합니다.

데이터 소스#

연결 테스트가 실패합니다. Host에 localhost 를 썼다면 host.docker.internal 로 바꾸세요. 연결을 시험하는 쪽이 컨테이너 안의 데이터 패브릭이라, 그 안의 localhost 는 컨테이너 자신입니다(11장).

데이터 소스를 등록했는데 데이터 스키마가 비어 있습니다. 정상입니다. 데이터 스키마 캔버스는 DDL · 코드 분석(13장)이나 사용자 입력으로 채워집니다. 등록한 DB의 테이블은 데이터 소스 카드를 눌러 실제 DB 테이블에서 봅니다.
