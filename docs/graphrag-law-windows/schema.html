골든 퀘스천에서 스키마 설계하기

답해야 할 질문 다섯 개를 Claude Code에 주고, 위험물안전관리법 PDF 3개를 직접 열어 본 뒤 노드·관계·속성을 설계하게 합니다. Windows에서 Claude Code를 처음 여는 방법, 설계를 검토하고 고쳐 달라고 요청하는 프롬프트, 질문별 그래프 탐색 경로와 제약·색인 파일을 실행 기록과 함께 살펴봅니다.

무엇을 · 왜#

스키마(온톨로지)는 그래프의 틀입니다. 어떤 노드를 두고 무엇을 관계로 연결할지 정하므로, 같은 법령으로도 쓰임새에 따라 전혀 다른 그래프가 나옵니다. 그래서 모델부터 그리지 않고 답해야 할 질문 목록에서 출발합니다. 이 교재의 구축 목적은 「위험물 안전관리 매뉴얼 내부 구축」이고, 질문은 0장의 골든 퀘스천 5개입니다.

이 장에서는 그 질문을 Claude Code에 그대로 주고, 코드를 만들기 전에 PDF를 열어 실제 조문 형태부터 확인하게 합니다. 설계 결과는 사람이 검토하고 한 번 더 수정을 요청한 뒤 커밋합니다. 틀(스키마)을 채우는 인스턴스(지식 그래프)는 6장에서 만듭니다.

시작하기 전에

Neo4j 창이 떠 있고, 4장 끝의 「지우기」로 맛보기 그래프를 지워 DB가 비어 있어야 합니다(MATCH (n) RETURN count(n)이 0). 위험물안전관리법 PDF 3개를 내려받아 두었는지 확인합니다(시작하기).

따라 하기#

  1. 법령 PDF 3개를 실습 폴더에 넣고 커밋합니다. 시작하기에서 국가법령정보센터(law.go.kr)로 받은 위험물안전관리법 법률·시행령·시행규칙 PDF입니다. 브라우저가 내려받은 곳(보통 내 PC\다운로드)에서 이름이 「위험물안전관리법」으로 시작하는 파일만 복사합니다. 왜 하나요? Claude Code는 실습 폴더 안의 파일만 읽습니다. 원본 PDF를 커밋해 두면 나중에 판본이 바뀌어도 어느 PDF로 만든 그래프인지 기록이 남고, 6장에서 원문과 대조할 기준이 됩니다. ▶ 작업 창(Windows PowerShell)에 입력 
    Set-Location C:\lab\law-graph
New-Item -ItemType Directory -Force pdf | Out-Null
Copy-Item "$HOME\Downloads\위험물안전관리법*.pdf" pdf\
Get-ChildItem pdf -Name
(Get-ChildItem pdf -Filter *.pdf).Count      # 3 이 나와야 합니다
git add pdf; git commit -qm "위험물안전관리법 PDF 3개"
    !!! warning "개수가 3이 아니면 커밋 전에 멈추세요" Copy-Item은 와일드카드(*)에 맞는 파일이 하나도 없어도 오류 없이 그냥 넘어갑니다(실제 PC에서 확인). 숫자가 0이면 PDF가 다운로드가 아닌 다른 폴더에 있는 것입니다. 파일 탐색기에서 PDF가 있는 폴더를 찾아 "$HOME\Downloads\…" 부분을 그 경로로 바꿔 다시 실행합니다. 출력 예시 
    위험물안전관리법 시행규칙(행정안전부령)(제00628호)(20260701).pdf
위험물안전관리법 시행령(대통령령)(제36432호)(20260701).pdf
위험물안전관리법(법률)(제20231호)(20250807).pdf
    파일 이름 끝의 날짜가 시행일입니다. 다운로드한 날짜에 따라 판본이 달라지면 6장의 조 개수도 달라질 수 있습니다. 파일 이름에 괄호와 한글이 들어 있지만 PowerShell과 Git for Windows는 그대로 다룹니다. git status에서 한글 파일 이름이 \354\234…처럼 보이면 git config --global core.quotepath false를 한 번 실행하세요.
  2. 실습 폴더에서 Claude Code를 엽니다. claude를 처음 실행하면 글자 테마 선택 → 보안 안내 → 폴더 신뢰 확인이 차례로 나옵니다. 폴더 신뢰 확인의 기본 선택은 No, exit라서 그냥 Enter를 누르면 Claude Code가 꺼집니다. ↓ 키로 Yes, I trust this folder를 고른 뒤 Enter를 누릅니다. 왜 하나요? Claude Code는 실행한 폴더를 작업 범위로 삼습니다. 실습 폴더에서 열어야 PDF를 읽고 결과 파일을 그 폴더에 만들며, 폴더 밖의 파일은 건드리지 않습니다. Claude Code 화면 예시 
     Accessing workspace:
 …/law-graph
 Quick safety check: Is this a project you created or one you trust? …
 ❯ No, exit
   Yes, I trust this folder
    Windows에서는 PowerShell 창에서 C:\lab\law-graph로 이동하고 env.ps1을 점 소싱한 뒤 claude를 실행합니다. 처음 실행하면 브라우저가 열려 Claude 계정 로그인을 요청합니다. ▶ 작업 창(Windows PowerShell)에 입력 
    Set-Location C:\lab\law-graph
. .\env.ps1
claude
    Windows용 Claude Code는 Claude가 셸 명령을 실행할 때 Git for Windows의 Git Bash를 씁니다. 그래서 승인 창에 나오는 명령은 PowerShell이 아니라 bash 문법(ls, grep, /c/lab/law-graph 같은 경로)입니다. 사람이 직접 입력하는 명령만 PowerShell로 쓰면 됩니다. Git Bash를 찾지 못한다는 오류가 나오면 Git for Windows를 설치한 뒤 새 창에서 다시 실행합니다. 시작 화면에는 Claude Code 버전(기록 당시 v2.1.331)과 모델·플랜이 나옵니다(이 기록은 Fable 5.2 with medium effort · Claude Ultra, 사용자마다 다릅니다). 기본 권한 모드에서는 명령을 실행하거나 파일을 쓰기 전에 매번 승인을 요청합니다.
  3. 설계를 요청합니다(P1). 구축 목적, 골든 퀘스천, 「아직 코드는 만들지 말고 PDF부터 열어 보라」는 작업 순서, 결과 파일 이름을 한 번에 전달합니다. 여러 줄을 입력할 때는 줄 끝에서 \ + Enter를 눌렀습니다. 왜 하나요? 답해야 할 질문이 정해져야 어떤 노드와 관계가 필요한지 정할 수 있습니다. 코드를 짜기 전에 PDF를 먼저 보게 하면, 실제 조문의 모양(항 없이 호만 있는 조, 가지번호 등)을 설계 단계에서 반영해 나중에 고칠 일이 줄어듭니다. ▶ Claude Code 입력창에 붙여 넣기 
    우리 회사에 「위험물 안전관리 매뉴얼」을 내부 구축하려고 해. pdf/ 폴더에 위험물안전관리법 PDF 3개(법률·시행령·시행규칙)가 있어. 이 PC는 Windows 이고, 코드는 나중에 PowerShell 에서 uv 로 실행할 거야. 이걸 Neo4j 그래프로 만들어서 아래 골든 퀘스천에 근거 조문과 함께 답하게 하고 싶어.
1. 제조소등에서 위치·구조·설비 변경 없이 저장·취급하는 위험물의 품명·수량(지정수량 배수)을 바꾸려면 언제까지 누구에게 신고해야 하는가?
2. 위험물안전관리자가 해임되거나 퇴직하면 관계인은 며칠 안에 다시 선임해야 하고, 선임한 뒤에는 어떤 절차를 밟아야 하는가?
3. 정기점검을 마친 제조소등의 관계인은 점검 결과를 언제까지 누구에게 제출해야 하는가?
4. 제조소등에서 위험물 유출 사고가 발생했을 때 관계인과 이를 발견한 사람은 각각 무엇을 해야 하며, 관계인이 응급조치를 하지 않으면 누가 명령할 수 있는가?
5. 안전관리자 선임 의무(제15조)나 정기점검 의무(제18조)를 지키지 않으면 어느 벌칙·과태료 조항이 적용되는가?
아직 코드는 만들지 말고, 먼저 PDF 를 열어 실제 조문 모양을 확인한 다음 "이 질문들에 답하려면 어떤 노드·관계·속성이 필요한가"부터 스키마(온톨로지)를 설계해 줘. 질문마다 그래프에서 어떤 경로로 답을 찾는지도 보여 줘.
결과는 schema.md(노드·관계·속성 표 + mermaid 그림)와 schema.cypher(제약·색인)로 저장하고, 골든 퀘스천은 golden-questions.md 에 그대로 적어 둬.
    Claude는 PDF의 텍스트를 추출해 조 제목·「제N조」 인용·「대통령령으로 정하는」·벌칙 문구를 훑습니다. Windows의 Git Bash에는 pdftotext가 없으므로, Claude는 보통 uv run --with pymupdf python -c …처럼 PyMuPDF로 텍스트를 뽑습니다. 어느 쪽이든 읽기만 하는 명령이면 1(Yes)로 승인합니다. 파일을 만들 때는 1을, 같은 세션의 다음 파일부터는 2(이 세션 동안 편집은 묻지 않기)를 고르면 편합니다. 기록에서는 4분 56초 뒤 schema.md(405줄)·schema.cypher(86줄)·golden-questions.md가 생성됐습니다.
  4. 설계를 읽고 고쳐 달라고 합니다(P2). 첫 설계에는 골든 퀘스천용 의무(Norm) 14건을 손으로 적은 표까지 들어 있었습니다. 검토하면서 두 가지 문제를 발견했습니다. 질문의 낱말과 조문의 표기가 다르다는 점, 그리고 손으로 만든 14건은 다른 법으로 확장하기 어렵다는 점입니다. 왜 하나요? AI의 설계를 그대로 받아들이지 않고 사람이 검토하는 것이 바이브 코딩의 핵심입니다. 질문의 낱말과 조문 표기가 다르다는 문제는 지금 잡지 않으면 9장에서 「검색이 안 된다」로 드러납니다. ▶ Claude Code 입력창에 붙여 넣기 
    schema.md 읽어 봤어. 두 가지 고쳐 줘.
1. 질문에 쓰는 말과 조문 표기가 달라. 질문은 「안전관리자」「시·도지사」「위치·구조·설비」(가운뎃점 ·)라고 쓰는데 PDF 는 「위험물안전관리자」「시ㆍ도지사」(ㆍ)「특별시장ㆍ광역시장ㆍ…ㆍ도지사」로 쓰고, 「제조소등」은 「제조소ㆍ저장소 및 취급소」야. Term·Actor 에 대표 이름, 별칭(aliases), 가운뎃점을 맞춘 정규화 이름을 두고, 정의 조항(제2조)과 「이하 "…"라 한다」 약칭에서 별칭을 채우는 규칙을 적어 줘. 질문의 낱말을 어떤 색인으로 이 노드에 연결하는지도 Q2 를 예로 보여 줘.
2. Norm 14건을 손으로 만드는 건 다른 법으로 넓히기 어려워. 이번 적재는 구조층·참조층·Term 까지만 하고, Actor·Norm(의미층)은 다음 단계에서 LLM 으로 조문에서 뽑아 붙이는 걸로 표시해 줘. 의미층 없이 다섯 질문에 어떤 경로로 답하는지도 고쳐 줘.
3. 나중에 내가 직접 Cypher 로 검증할 수 있게 속성 이름은 이렇게 맞춰 줘: 법령 노드 Law 의 키는 lawId(법령 이름), 조문에 inCorpus(적재한 법령이면 true). 조·항·호·목 노드는 공통 레이블 Provision 과 키 pid(예: 위험물안전관리법:제15조:제2항), label(제2항), citation(위험물안전관리법 제15조제2항), lawId, articleNo, articleSub(가지번호, 없으면 0), text, normText, isCurrent, status(현행/삭제), order.
    4분 36초 뒤 schema.md는 501줄, schema.cypher는 106줄이 됐습니다.
  5. 커밋합니다(P3). 「커밋해 줘」라고만 하자 Claude는 main에 바로 넣지 않고 schema-design 브랜치를 새로 만들어 커밋했습니다. 이 실습은 브랜치 하나로 진행하므로 이렇게 이어서 요청했습니다. 왜 하나요? 검토를 마친 설계를 커밋해 두면 6장의 코드가 이 설계를 기준으로 만들어지고, 나중에 설계를 바꿀 때 무엇이 바뀌었는지 비교할 수 있습니다. ▶ Claude Code 입력창에 붙여 넣기 
    좋아, schema.md·schema.cypher·golden-questions.md 를 커밋해 줘.
    ▶ Claude Code 입력창에 붙여 넣기 
    이 실습은 main 하나로 할게. main 으로 합치고 앞으로도 main 에 커밋해 줘.
    Claude는 git merge --ff-only로 합치고 브랜치를 지웠습니다. 이어서 「main에 바로 커밋」이라는 메모를 자동 메모리에 남기고, 실습 폴더 밖(Windows에서는 %USERPROFILE%\.claude\projects\…\memory\MEMORY.md)에 색인 줄을 추가하는 명령의 승인을 요청했습니다. 경로가 실습 폴더 밖이라 3(No)으로 거절하고 「메모리 파일은 건드리지 말고 넘어가자. 실습 폴더 밖은 고치지 마.」라고 답했습니다. 승인 창에서는 명령의 경로를 확인하고 선택하세요.

확인#

세 파일이 main에 반영됐는지 확인합니다. 커밋 번호와 메시지는 사용자마다 다릅니다(아래는 이 실습의 기록이며, 첫 커밋 줄은 생략했습니다).

▶ 작업 창(Windows PowerShell)에 입력

Get-ChildItem schema.md, schema.cypher, golden-questions.md
git log --oneline

Claude가 낸 설계#

모델이 작성하는 설계와 문장은 실행할 때마다 달라질 수 있습니다. 아래는 P2까지 반영해 커밋한 설계 기록입니다. 노드·관계의 종류는 법령 수와 상관이 없으므로, 여러분의 설계도 비슷한 틀이 나오는 것이 정상입니다. 표의 예는 모두 위험물안전관리법입니다.

관계#

관계 방향 뜻
ENFORCES Law → Law 시행령·시행규칙이 모법을 시행
HAS_ARTICLE Law → Article 법령의 조
HAS_PART Provision → Provision 조→항→호→목. 항이 없으면 조→호
REFERS_TO {kind, raw} Provision → Provision 조문 인용(인용·준용·예외·양벌). 법령을 넘나듦
IMPLEMENTS {kind, raw} Provision → Provision 하위법령 조문이 「법 제N조…에 따라」로 상위 조항을 받음(위임정의·절차·권한위임)
PENALIZES {raw} Provision → Provision 벌칙·과태료 호가 지목한 위반 조항
IMPOSES Provision → Sanction 형량 문구가 있는 조·항
USES_ANNEX Provision → Annex 별표·서식 언급
CITES_LAW {raw} Provision → Law 조 번호 없는 법령 인용, 묶음 밖 법령
DEFINED_IN Term → Provision 정의·약칭이 있는 조문
MENTIONS Provision → Term 조문에 용어(대표 이름·별칭)가 나옴

골든 퀘스천마다 어느 경로로 답하나#

모든 질문은 같은 두 단계를 거칩니다. 진입: 질문의 낱말로 조문을 찾습니다(용어 열쇠 + 전문 색인, 조 번호가 있으면 바로). 펼치기: 찾은 조문이 속한 조 전체를 가져오고, 하위법령(IMPLEMENTS)·서식(USES_ANNEX)·조 안 인용(REFERS_TO)·벌칙(PENALIZES → IMPOSES)을 따라갑니다. 기한과 상대방은 그래프의 값이 아니라 조회된 조문에서 LLM이 읽어 냅니다.

질문 진입 펼치기에서 도달하는 조문
Q1 품명·수량 변경신고 법 제6조제2항 ← IMPLEMENTS{권한위임} 시행령 제21조제2호 · ← IMPLEMENTS{절차} 시행규칙 제10조 → 별지 제19호서식 · ← REFERS_TO{예외} 제6조제3항 · ← PENALIZES 제39조제1항제3호 → 과태료

참고 — Claude가 만든 내용(직접 입력하지 않음)

// 질문 안에 Term 의 열쇠(정규화한 대표 이름·별칭)가 들어 있나
MATCH (t:Term {family: '위험물안전관리법'})
WHERE any(k IN t.normKeys WHERE $qKey CONTAINS k)
RETURN t.termId, t.name, [k IN t.normKeys WHERE $qKey CONTAINS k] AS 맞은_열쇠;

질문의 「위험물안전관리자」는 Term 「안전관리자」의 별칭 열쇠로, 「관계인」은 대표 이름으로 잡힙니다. 이 연결이 실제로 어떻게 동작하는지는 7장과 9장에서 살펴봅니다.

schema.cypher#

제약과 색인을 모아 둔 파일입니다. 6장의 ingest.py가 적재 전에 이 파일을 읽어 실행합니다. 여러 번 실행할 수 있도록 모두 IF NOT EXISTS를 사용합니다.

종류 이름
유일 제약 5개 law_id, provision_pid, annex_id, sanction_id, term_id
범위 색인 8개 term_family, term_norm_name, provision_law_article, provision_level, provision_current, provision_citation, law_family, sanction_type
전문 색인 2개(cjk) provision_text(조 제목·정규화한 텍스트), term_text(용어 searchText)
주석으로 둔 것 의미층(Norm·Actor) 제약과 색인, 벡터 색인

참고 — Claude가 만든 내용(직접 입력하지 않음)

// 조·항·호·목은 모두 :Provision 라벨을 함께 갖는다(:Article / :Paragraph / :Item / :SubItem).
CREATE CONSTRAINT provision_pid IF NOT EXISTS
FOR (p:Provision) REQUIRE p.pid IS UNIQUE;

// "제15조" 처럼 조 번호로 바로 찾기
CREATE INDEX provision_law_article IF NOT EXISTS
FOR (p:Provision) ON (p.lawId, p.articleNo, p.articleSub);

// 한국어는 기본 분석기로 잘 쪼개지지 않으므로 cjk(2글자 단위) 분석기를 쓴다.
CREATE FULLTEXT INDEX provision_text IF NOT EXISTS
FOR (p:Provision) ON EACH [p.title, p.normText]
OPTIONS { indexConfig: { `fulltext.analyzer`: 'cjk' } };

(파일에서 발췌했습니다. 주석은 Claude가 쓴 그대로입니다.) 4장에서 손으로 해 본 cjk 분석기를 Claude도 스스로 골랐습니다.

다른 설계 대신 이것을 고른 이유#

법령 그래프를 사람이 처음 그리면 흔히 법령·장·조·항·호·소관부처·하위법령·기업·인허가증처럼 문서 구조를 그대로 옮긴 노드를 만듭니다. 이번에는 Claude Code가 골든 퀘스천을 바탕으로 설계했고, 그래서 다음과 같은 선택을 했습니다.

항목 흔한 다른 선택 이 교재 왜
장 Chapter 노드 + HAS_CHAPTER chapter·chapterTitle 속성 다섯 질문의 경로 어디에도 장을 거치는 단계가 없습니다. 장은 찾은 조와 함께 보여 줄 정보이므로 속성이면 충분합니다
위임 DELEGATES_TO(위임하는 쪽 → 하위법령) IMPLEMENTS(하위법령 조문 → 상위 조항), 방향이 반대 하위법령 조문이 「법 제N조제M항에 따라」라고 상위 조항을 직접 적으므로, 해당 조문에서 규칙을 적용해 항 단위로 추출할 수 있습니다
벌칙 벌칙 조문 → 근거 조문 REFERS_TO(조 단위) PENALIZES(벌칙 호 → 위반 항) + IMPOSES → Sanction Q5가 「어느 벌칙 호가 어느 의무에」를 묻고, 형량 상한을 값으로 꺼내야 합니다
용어 없음 Term(별칭·정규화 열쇠) + MENTIONS 질문의 낱말(「위험물안전관리자」「시·도지사」)과 조문 표기가 다릅니다(P2)
인허가증 Company·Permit + BASED_ON 없음 이번 구축 목적(내부 매뉴얼)에는 회사·인허가증이 나오지 않습니다
범위 위험물안전관리법 1개 위험물안전관리법 3종(법률·시행령·시행규칙) 법률과 시행령·시행규칙이 서로 인용합니다

확인 문제#

설계를 요청하면서 「아직 코드는 만들지 말고 먼저 PDF를 열어 보라」고 한 까닭은 무엇인가요?

실제 조문 형태에 따라 스키마가 달라지기 때문입니다. Claude는 PDF를 보고 항 없이 호가 붙는 조, 가지번호, 벌칙 호가 위반 조항을 직접 지목하는 문장, 같은 조 번호가 두 번 나오는 시행 예정 판본, 본문에 끼어든 쪽 머리말을 찾아 설계에 반영했습니다. 코드를 먼저 짰다면 적재한 뒤에야 알았을 것들입니다.

Term의 aliases와 members는 어떻게 다른가요?

aliases(별칭)는 같은 것을 가리키는 다른 표현입니다. 예를 들어 「안전관리자」의 별칭은 「위험물안전관리자」입니다. members(구성원)는 그 말에 속하는 것들입니다. 「제조소등」의 구성원은 제조소·저장소·취급소이며, 「제조소」가 곧 「제조소등」은 아닙니다. 둘을 섞으면 답변에서 서로 다른 것을 같은 것으로 취급하게 됩니다.

첫 설계의 Norm 14건을 지우고 의미층을 다음 단계로 미룬 이유는 무엇인가요?

손으로 적은 14건은 골든 퀘스천 다섯 개에만 맞춘 것이라 다른 법령이나 새 질문으로 확장할 수 없습니다. 구조층·참조층·용어층만으로도 다섯 질문 모두 근거 조문에 도달할 수 있으므로, 의미층은 LLM으로 조문에서 정보를 추출해 연결하는 방법(7장)으로 만들기로 했습니다.

IMPLEMENTS 관계의 화살표는 어느 쪽을 가리키나요?

하위법령 조문에서 상위 조항을 가리킵니다. 예를 들어 시행규칙 제53조 → 법 제15조제3항입니다. 하위법령 조문이 「법 제15조제3항에 따라」처럼 상위 조항을 적기 때문에 해당 조문에서 이 방향으로 관계를 추출합니다. PBL 특강 교재의 DELEGATES_TO와는 방향이 반대입니다.
